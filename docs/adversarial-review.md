# 三轮对抗式字形审核 —— 每个码位过三轮，每轮攻击上一轮的结论

**一句话结论**：4161 个码位各过三轮**互相独立**的攻击面，机器筛出 169 例高危，
由人工 8 倍逐格裁决后 **0 例确认缺陷**；链条级核验（源字体重渲 + 产物独立读）
4158/4158 **逐字节一致**。

工具：`tools/fontgen/adversarial_review.py`
裁决台账：`reports/adversarial/adjudication.json`（169 条，逐字带理由）
机器结论：`reports/adversarial/{round1,round2,round3,summary}.{json,md}`

---

## 1. 为什么在两轮目视复核之后还要再来一轮

前两轮已经把**覆盖**做满了：

- 8 条 lane 目视复核 4140 / 4140（`docs/glyph-review-protocol.md`）——
  那是 **4140 字符集那一版**的快照；2026-10-24 补入 21 个符号后字符集为 4161，
  新增字形另行逐个 12px 点阵目视（见 [`glyph-identity-verification.md`](glyph-identity-verification.md) §5.3）；
- 修复后对换源导致的 65 个字做定点重核，65/65 全过。

但两轮用的是**同一种攻击面**：并排对照图 + 人眼判断"我方画的到底是不是这个字、
笔画结构有没有塌"。用同一把尺子再量一遍，得到的不是独立证据，而是**相关的重复命中**——
三轮一致地错，比错一次更难发现（量具错的时候，表现和对的时候一模一样）。

所以这一轮换的不是"再量一遍"，而是换**攻击面**，并且让每一轮去**证伪上一轮**：

| 轮 | 攻击面 | 量具（互相独立） | 攻击的是谁 |
|---|---|---|---|
| 1 | 身份反查 | 多腔镜像 / 像素级反向近邻 / 混淆组拓扑规则 / 我方近重复 | 「身份错误 0 例」 |
| 2 | 部件级结构 | 腔面积集合 / 二维部件格归属 / 桥接间隙 | 「结构劣化已修完」 |
| 3 | 链条 | 源字体重渲 / 产物独立读 / 结论对撞 | 「我方这一列 = 字体的字形」 |

前两轮都默认了一件事：**我方这一列的位图就是字体的字形**。第三轮去证伪这个前提本身——
这是前两轮根本没有触碰过的一层。

## 2. 量具自检（不拿自己的尺子给自己作证）

每个新量具写两份**不同代码路径**的实现（洪水填充 BFS / 并查集），全量比对一致才算数。
这一条不是形式：项目历史上两份"看起来一样"的腔数实现里，有一份把贴边区域算成了腔，
800 次比较里 667 次不一致，而它错的时候表现和对的时候一模一样。

| 自检项 | 结果 |
|---|---|
| 两份实现一致性（我方 4158 个字形） | **0 处分歧** |
| 两份实现一致性（参考 81137 个字形） | **0 处分歧** |
| 阳性对照：注入"填掉最大的腔"，必须被检出 | **200 / 200** |
| 阴性对照：自己对自己比，必须全静 | **0 次误报** |

## 3. 阈值怎么来的 —— 三次量具翻车记录

这一节是本轮最有价值的部分。**三个阈值都翻过车**，而且每次翻车的表现都是
"看起来像在工作"。定论：**阈值只能来自对照集的经验分布，且必须按类别分开标定。**

### 3.1 翻车一：近邻反搜的量化太粗 → 阈值算成 0，3908 个字全命中

第一版用 6 维密度特征（腔数 / 笔画分段 / 墨量 / 宽高）做反向近邻。
结果：不同汉字大量撞出**同一个特征向量**，距离恒为 0，"我方离谁更近"这个问题整个退化；
对照集上标定出的阈值 p99.9 = **0**，于是 4139 个字里 3908 个"命中"。

> 修法：改用**16×16 画布上的逐像素汉明距离**（不重采样，`np.bitwise_count` 弹位数）
> + 8 × |字腔数差|。像素级距离不会因为量化而退化。

### 3.2 翻车二：哨兵值污染阈值 → 阈值 999982，整个屏失灵

Zpix 缺 12 个假名（ゔゕゖ゙゚゛゜ヷヸヹヺヿ）。这些码位没有"同码位参考"可比，
代码里给 `d_self` 塞了 `1e6` 当哨兵 —— 结果哨兵值混进了对照集的经验分布，
把 p99.9 阈值顶到 **999982**，屏幕等于关掉了。

> 修法：参考集里没有的码位**直接跳过**（那一路交给覆盖完整的 Unifont），不塞哨兵值。

### 3.3 翻车三：身份规则推广过头 → 2548 个字命中（62%）

`route_rule.identity_confused` 的原语义是：**只在我方渲染成同一张位图的码位组内比对**，
且**只比字腔数**这一个标量。我把它推广成"拓扑三元组 + 全码位两两比"，结果 2548 个字命中。
原因：不同汉字的（腔数, 横笔, 竖笔）三元组大量重合，"我方 != 参考对同码位"这个条件几乎恒真。

> 修法：回到严格语义 —— 混淆组内比对 + 单标量（字腔数）。推广可以，但**必须先证明
> 判别式还有分辨力**，不能因为"更严格"就以为"更准"。

### 3.4 定论：阈值 = 对照集的经验分布，**且按类别**

对照集 = 历史复核**没有**标注任何问题的 3968 个字。阈值取自它们的经验分布，
于是每个命中都自带一句"同样的量在已知正确的字上会响几次"。

按类别分开标定是必须的：ASCII/假名走 MS Gothic（本来就是 12px 点阵），
与 12px 的 Zpix 几乎同源；汉字走 SimHei 轮廓栅格化或 Fusion 点阵，画风差一个量级。
同一个阈值对 ASCII 太松（漏报）、对汉字太紧（误报）。

实测噪声底（对照集 3968 字）：

| 量 | 对照集中位 | 对照集 p99 | 说明 |
|---|---|---|---|
| 腔数差（我方 − Zpix） | 0 | **3**（最大 5） | 我方比参考多 3 腔以内属常态 |
| 腔面积 L1（绝对像素） | 2 | 21.5 | 比值不行，绝对量才稳 |
| 桥接处数 | 0 | **3** | 笔画被搭桥本来就常见 |
| 单部件腔数缺口 | 0 | 1 | 局部塌陷的自动召回上限就在这里 |

> 这张表把项目文档里"自动判据对局部塌陷的召回率只有 5/29"那句话**量化**了：
> 不是判据写错了，是**这把尺子的分辨力**就到这儿了。

## 4. 第一轮：身份反查（命中 60 条）

| 判据 | 命中 | 作用 |
|---|---|---|
| `COUNTER_GAINED` | 28 | **镜像判据**：现有硬检查只有"参考有腔、我方 0 腔"（`COUNTER_LOST`）这一侧，**没有**"我方比参考多腔"这一侧。而历史上唯一的身份错误（U+3099 ゙ 画成 ゜）正是**多**了 1 腔 |
| `REVERSE_NN` | 8 | **像素级反向近邻**：不问"我方离同码位参考有多远"，而问"我方离**别的码位**的参考有多近"，在 Zpix 全 22228 字形里反搜 |
| `OWN_EXACT_DUP` | 7 | 我方两个字渲染成完全相同的位图（标点天然同形） |
| `OWN_NEAR_DUP` | 5 | 我方两个字只差 0–2 像素（`6`/`8`、`8`/`9`） |
| `REF_AMBIGUITY_DIVERGENCE` | 2 | 参考把两个码位画成同一张，我方却画得不同 —— **我方是异类** |
| `IDENTITY_RULE` | **0** | 混淆组内比拓扑标量：没有任何码位被换字 |

结论：

- **身份错误 0 例**，与目视结论一致；U+3099 的换字修复**仍然成立**（第一轮不再命中它）。
- 8 例 `REVERSE_NN` 逐格放大后确认**都是同一个字**：近邻指向的"别的字"是
  画风差异造成的像素距离假象（例：扇 靠近「泉」、算 靠近「笡」、颜 靠近「颔」）。
- 2 例 `REF_AMBIGUITY_DIVERGENCE` 是 `0` 与 `O`：**Zpix 把这两个画成同一张，我方区分开了** ——
  这一条是我方更对，参考有歧义。

## 5. 第二轮：部件级结构攻击（命中 139 条，量到 4145 字）

放弃"全字腔数"这个已经证明没有分辨力的量，改在**部件尺度**上找：

| 判据 | 命中 | 抓什么 |
|---|---|---|
| `BRIDGED_GAP` | 39 | 同一行/列**墨点数相同但分段数变少** —— 笔画被搭桥连上（横画并成实心带） |
| `HOLE_DEFICIT` | 31 | 参考有腔、我方没有（有腔被填死） |
| `MAX_CAVITY_GAP` | 30 | 最大的那个腔没了（腔被填实） |
| `CAVITY_AREA_L1` | 30 | 腔的**面积集合**对不上（腔数持平但面积差很多） |
| `COMPONENT_DEFICIT` | 7 | 全字腔数**持平**，但某个**部件格**里参考有腔我方没有 —— 定位"哪一块塌了" |

最有信息量的一组：`COMPONENT_DEFICIT` 的 7 例里有 **5 例（晒 栖 洒 酒 西）指向同一个部件「西」**。
同一个根因被 5 个不同的字同时暴露 —— 这正是全局腔数看不见的东西。

但逐格看完之后：参考把「儿」的笔画**连到框上**围出小腔，我方在 12px 网格上**留了缝**。
结构是同一个「西」，差异在连接方式 —— 画风差异，不是结构丢失。

## 6. 第三轮：链条攻击（命中 19 条）

前两轮都默认「我方这一列 = 字体的字形」。本轮证伪这个前提：

| 检查 | 结果 |
|---|---|
| **PROVENANCE**：每个码位的位图是否等于它**声称**的源字体渲染出来的字（用 PIL 独立重渲，逐字节比） | **4158 / 4158 一致，0 不一致** |
| **PRODUCT_SYNC**：独立读 `dist/PixelFontPC98-12.bdf` 与当前源逐字比（不走构建脚本） | **4158 / 4158 一致，0 不一致** |
| `REGRESS_IDENTITY` | 0（U+3099 修复仍成立） |
| `REGRESS_DEGRADED` | 1（糯 U+7CEF：历史判为劣化并换过源，第二轮仍命中）→ **目视裁定不是缺陷** |
| `UNSURE_CONFIRMED` | 18（109 个历史"存疑"里 18 个被自动量命中 —— 但"存疑"的定义正是"笔画比参考密"，等于把已知结论重新数了一遍） |
| `NEW_HIT` | 回灌后不再重复计数（见下） |

**结论回灌通道**：目视裁决过的字写进 `reports/adversarial/adjudication.json`，
下一次跑就不再报成"新发现"。项目里已有同样的先例（目视结论 `--force-from-review`
回灌到路由推导）—— 没有这条通道，每一轮都会把同一批字重新数一遍，
看起来像"又发现了很多问题"。

## 7. 目视裁决（这一步只能由人眼做）

**方法**：8 倍最近邻放大，每格 `我方 / Zpix / Unifont`（身份类再加第 4 格"嫌疑字"）并排，
按 `docs/glyph-review-protocol.md` 第 5 节的口径逐格判断 —— 只在**结构信息丢失**时判缺陷，
画风差异不判。底本是 `reports/adversarial/png/focus_01..15.png`（不入库，可一键重生成）。

**覆盖**：机器命中的 **169 例全部逐格看过**，无一抽样。

**裁决结果：0 例确认缺陷。** 归因分布：

| 归因 | 数量 | 含义 |
|---|---|---|
| `style_density` | 106 | 我方 12px 渲染比参考密（笔画连腔），但骨架仍可追踪 |
| `looser_than_ref` | 25 | 我方比参考**松**（腔更多）—— 参考反而更密 |
| `punct_homoglyph` | 9 | 标点/数字在 12px 下天然同形（`'` `,` / `6` `8` …） |
| `grid_limit` | 6 | 该字在 12px 网格下本就放不下参考那么多封闭空间 |
| `identity_ok` | 6 | 放大后确认是我方就是标注的那个字 |
| `component_style` | 5 | 部件的连接方式不同（参考连成闭环、我方留缝） |
| `reference_ambiguity` | 2 | 参考把两个码位画成同一张，我方区分开了 |
| `ref_divergence` | 1 | 已知参考集画风分歧（舆 U+8206） |

几条值得单独记的：

- **「西」这一族**（西 晒 栖 洒 酒）—— 一个部件的连接方式差异，5 个字同时暴露；
- **辨 / 辩 / 辫** —— 三个高度易混的字，我方中间部件分别是刀、言字旁、绞丝旁，**区分清楚**；
- **0 / O** —— 参考把两者画成同一张，**我方更对**；
- **糯 U+7CEF** —— 历史判为"劣化"并换过源，本轮第二轮仍命中，但放大后结构完整，
  判为画风差异。**这条"劣化回归"是量具的误报，不是字体的回归。**

## 8. 本轮新增了什么（即使没发现新缺陷）

1. **一套标定过的自动量**，每个命中都自带噪声底（对照集分布）——此前项目里的自动判据
   只有"绝对阈值 12"这样的拍脑袋值，且没有报出"它在已知正确的字上会响几次"。
2. **169 例逐格目视裁决台账**（`adjudication.json`），可复用的"已排除"记录 ——
   下一轮不必重复劳动，也不会重复报同一批字。
3. **链条级核验独立成步**：溯源（源字体重渲）与产物同步（独立读 dist/）从构建脚本的自证里剥了出来。
4. **三次量具翻车的完整记录**（第 3 节）—— 这是可以直接复用的工程经验：
   阈值必须来自对照集、必须按类别、哨兵值不得混进标定集。
5. **2026-10-24：机器抓出一个真缺陷 —— U+005C 反斜杠被画成了 ¥。**
   补入 U+00A5 日元符号后，第一轮的"我方近重复"检测报出两者**整格逐字节完全相同**。
   把位图打出来才看清：MS Gothic 按 **JIS 惯例**把 U+005C 画成 ¥（日文键盘的反斜杠
   键位就是 ¥）。这个缺陷一直存在，只是之前没有第二个 ¥ 形状的码位可比。
   修法是新增**非汉字码位的源例外**（`charset.SOURCE_OVERRIDES`）—— `ideo_route.json`
   只覆盖汉字，而这是 ASCII 码位带着源字体**语系惯例**的问题。详见
   [`word-compat.md`](word-compat.md) §5.2。

   这一条同时说明了这套审核的价值：**同一个"我方两个码位画得一样"的信号**，
   在没有第二个 ¥ 码位时是噪声，凑齐第二个之后就是缺陷 —— 判据本身没变，
   变的是被攻击的面。

## 10. 已知限制

1. **自动结构量对本字体没有分辨力**（对照集噪声底：腔数差 p99 = 3、桥接 p99 = 3）。
   第二轮的 137 条命中经逐格裁决后**没有一条是真缺陷** —— 这不是判据没用，
   是它只能筛高危，最终判定仍然只能靠人眼。本轮把这条限制**量化**了。
2. **独立参考只有 2 票**（Zpix / Unifont），且 Unifont 是 16px，与 12px 不可直接比像素；
   Fusion 对简体字不提供独立票（与 Ark 同构）。
3. **对照集依赖历史复核的结论**。若历史漏判，真缺陷会被当成噪声底吸收进阈值。
   第三轮是去攻击这个假设，但它只能证伪"结论—链条"这一层，**证伪不了目视本身**。
4. 本轮覆盖的是"机器量能触及"的结构特征（腔拓扑 / 面积 / 笔画分段 / 字节级溯源），
   不等于覆盖了所有可能的画法问题；**全字形的目视覆盖保证仍然来自前两轮那一轮的手工复核**
   （覆盖 4140 字符集那一版；2026-10-24 新增的 21 个符号另行逐个点阵目视）。
5. 16px 的 Unifont 在腔数上系统性多于 12px，**不可与 12px 的量混算**（本轮已按参考分源处理，
   但仍有残余的风格偏置）。
