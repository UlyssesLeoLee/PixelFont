## 结论先行

本项目的字体不是"看着差不多就行"的美术字体，而是**以 12×13 像素网格为硬约束、靠逐格像素一致性验收**的工程产物。因此测试规格的核心不是主观审美评价，而是**可判定的像素级判据**。当前家族共 **4,161 码位**，在 Windows GDI 路径下 12ppem 与 24ppem **4,161/4,161 逐格一致**、抗锯齿像素 **0**，这是目前唯一被证明"逐格还原设计"的渲染路径。FreeType 路径（Pillow / Chrome / Linux）**只有 24px 及以上**偏差为 0，12px 平均偏差 **19.00 px/字**（最坏 44）；非 12 整数倍字号（如 18ppem = 1.5 倍）笔画断裂且墨迹量偏细 **43%**。

由此得三条可执行结论：

1. **字号必须分档管理。** 只有 12 的整数倍字号（@96dpi 下 9 / 18 / 27 / 36 pt）属**精确档**，必须逐格一致；其余（10.5 / 12 / 24 pt）属**已知退化档**，测试目的是**记录退化表现**，不要求通过。
2. **渲染器必须分路径验收。** Windows / Word 走 GDI（已实测通过），FreeType / CoreText / 移动端是另一条路径，其中 **macOS、Android、iOS 至今未实测**，只能标「待验证」并写明验证方法。Word 自身的排版层（DirectWrite / Uniscribe）**未能直接观察**，不得用 GDI 结论替它背书。
3. **门禁必须自带阴性对照。** 若比较器抓不住抽格 / 错倍数 / 错字号 / 平移四类自身错误，门禁形同虚设。该自检已用 **18/18 通过**固化在 `tools/fontgen/verify_gdi.py`（454 行）。

覆盖面上有 4 类事实必须在测试中显式区分"缺陷"与"预期行为"：`€ ≠ ≤ ≥` 不被任何 Fusion 变体覆盖，走 MS Gothic / SimHei 路径（仍在字体中，属已知例外）；阿拉伯 / 希伯来 / 天城文 / 泰文**不在字符集内**，应表现为 `.notdef` 空心方框 —— **预期行为，不是失败**；参考字体自身缺字（Ark 缺 150、Zpix 缺 12）单列，不参与判定；`U+3097 ゗` / `U+3098 ゘` 被 `charset.EXCLUDE` 显式排除，同样以 `.notdef` 呈现。

整体验收现状：`tools/fontgen/verify_all.py`（196 行，8 步全链路）最近一次 **8/8 PASS**，全量回归 **0 error 0 warn**，对抗式审核三轮 60/139/19 命中、待裁决 0、已裁决非缺陷 169、确认缺陷 0。**已验证的部分到此为止**，其余一律按第 5 节的边界清单处理，不得在文档中夸大覆盖。

### 1.4 术语

| 术语 | 定义 |
|---|---|
| ppem | 每 em 的设备像素数。12ppem = 9pt @96dpi；24ppem = 18pt @96dpi |
| UPM | em 单位的字体坐标刻度，本项目 **768**；1 像素 = **64** 单位 |
| cell | 单字格，**12 × 13 像素**（宽 × 高） |
| 精确档 | 字号为 12 的整数倍，逐格还原设计 |
| 退化档 | 非 12 整数倍字号，出现笔画断裂 / 墨迹偏细，记录表现而非判失败 |
| 逐格一致 | 渲染结果与设计位图**逐像素**相同（不是"近似"） |
| 逐像素一致 | 两张位图所有像素完全相同 |
| 抗锯齿像素 | 渲染输出中既非纯黑也非纯白的像素数 |
| `.notdef` | 字符集外码位应渲染出的空心方框 |
| 精确性 | 整数倍缩放时设计网格与输出网格的对齐关系 |

## 2. 正文

### 2.1 测试策略与分层

分层原则：**越靠下越贵、越靠上越快**。L0/L1 在每次提交前跑，L2/L3 在合并前跑，L4/L5 定期或人工触发。

| 层 | 目的 | 触发时机 | 工具 | 通过标准 |
|---|---|---|---|---|
| L0 静态事实核对 | 确认度量、字符集、生产源与元数据常量未漂移 | 改动 `tools/fontgen/` 常量后 | `tools/fontgen/build_font.py::verify_ttf_metadata()` + 代码走查 | 四组 OS/2 不变量全过；UPM/cell/ascent/descent/advance 与底稿一致 |
| L1 构建期门禁 | 缺字、路由名单、回读一致性 | 每次构建 | `tools/fontgen/build_font.py` | 缺字门禁 + 路由名单门禁 + BDF/图集/TTF 回读校验全过 |
| L2 产物回归 | 产物位图 vs 源位图逐像素一致 | 每次构建后 | `tools/fontgen/regress.py`（1,034 行） | 4,161 字分 **43 批**，**0 error 0 warn** |
| L3 渲染兼容 | GDI 路径逐格还原 + 元数据可被系统选中 | 合并前 | `tools/fontgen/verify_gdi.py`（454 行） | 12ppem 与 24ppem **4,161/4,161** 逐格一致；抗锯齿 **0** |
| L4 对抗审核 | 独立攻击面找缺陷，不靠构建脚本自证 | 发布前 | `tools/fontgen/verify_all.py`（196 行）步骤 7 | 三轮命中均有裁决；**待裁决 0**、**确认缺陷 0** |
| L5 平台外延 | FreeType / CoreText / 移动端表现 | 人工触发 | 外部工具 | macOS / Android / iOS **尚未实测**，本层当前不产出通过结论 |

### 2.5 比较器自检（阴性对照）

比较器必须能抓住**自己会犯的错**，否则门禁形同虚设。四类注入错误各建一组用例，每组期望"比较器必须报错、不得判 PASS"。现有自检 **18/18 通过**。

| 编号 | 注入的错误 | 期望结果 |
|---|---|---|
| NC-01 | **抽格**：从一张正确位图里漏采某一像素格 | 比较器检出差异并判 FAIL；不得判 PASS |
| NC-02 | **错倍数**：用非 12 整数倍的缩放结果与设计位图比对 | 比较器检出差异并判 FAIL；不得判 PASS |
| NC-03 | **错字号**：用非目标 ppem（如 18ppem）的渲染结果比对 | 比较器检出差异并判 FAIL；不得判 PASS |
| NC-04 | **平移**：把位图整体平移 1 格后比对 | 比较器检出差异并判 FAIL；不得判 PASS |
| NC-05 | 组合错误（抽格 + 平移等叠加） | 仍被判 FAIL；不得因"部分重叠"漏检 |

自检用例集内嵌于 `tools/fontgen/verify_gdi.py`（454 行）中的比较器自检段。**18 例的逐条类型分布未在仓库留档** —— **待验证**，验证方法：读取 `tools/fontgen/verify_gdi.py` 的自检用例表并按上表类型归类计数。

### 2.8 排版与混排测试

度量前提（判据均由此推出）：UPM **768**；1 像素 = **64** 单位；cell **12 × 13**；基线 **ascent 11 / descent 2**（基线在第 11 行下方，cell 第 12 行），cell 高 **13**；advance 半角 **6**、全角 **12**；行高 **832** 单位 = **13** 像素（832 = 13 × 64）。

| 编号 | 用例 | 判据 | 验证方式 | 状态 |

| TY-01 | 中英混排 | 半角 advance **6**、全角 advance **12**；同一行内半角与全角字符基线落在同一 y 行（ascent 11 / descent 2），不产生半像素错位 | 同一行渲染后检查基线位置 | **待验证（未专门记录）** —— 验证方法：构造中英混排测试行，栅格化后测量基线 y 坐标 |
