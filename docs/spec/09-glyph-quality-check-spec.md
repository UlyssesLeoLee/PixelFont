# 09. 字形质量检查规范

> 文档编号：SPEC-09　|　状态：生效　|　适用家族：`PixelFont PC98 12`
> 上游依据：统一事实底稿 v2（2026-10-24 核实）　|　姊妹篇：SPEC-10 字体测试规格书（本文判"字形质量"，SPEC-10 管"测什么"）
> 仓库：`E:\PixelFont`　|　分支：`dev` 集成分支 / `main` 发布镜像（零分叉）　|　事实基线 HEAD：`4300fc1`

## 结论先行

PixelFont `PixelFont PC98 12` 的字形质量当前**可接受、可复现、可追溯**：全量质量门禁 `tools/fontgen/verify_all.py` 最近一次 **8/8 PASS**；4,161 码位回归 **0 error 0 warn**；GDI 在 12ppem 与 24ppem 下 **4,161/4,161 逐格一致**、抗锯齿像素 **0**；整数倍精确性 **12,483/12,483** 未破；对抗式审核三轮确认缺陷 **0**。因此本规范的重点**不是找茬**，而是把"什么算好字形"写成可执行、可复现、尽量零主观的判据。

同时有两点必须先说清，否则本规范会被误用：

1. **12px 层面只有 2 张独立票**（Zpix / Unifont）。生产源是 Fusion Pixel 12px 简体，而 Ark Pixel 是 Fusion 的**上游**——二者简体版 3,605 个共有汉字的结构签名逐个完全相同（结构距离均值 **0.00**、中位 **0.0**、绝对差 ≥ 12 的占比 **0.0%**），故 **Ark 不提供独立票**。结构类判据的样本量只有 2，**不得单独作为否决依据**。
2. **非整数倍字号下字形已知失真**：18ppem（1.5 倍）笔画断裂、墨迹量偏细 **43%**，**590/595** 字发生连通性变化（`中` 的连通域 **8 → 3**）。这是点阵字体的结构性边界而非实现缺陷；字形质量只在 12 的整数倍字号（12ppem = 9pt、24ppem = 18pt、36ppem = 27pt @96dpi）下判读。

| 判据维度 | 当前结论 | 证据来源 |
|---|---|---|
| 轮廓完整性 | 通过：UPM 768 整除 12（1px = 64 单位）、lsb = xMin、合并后轮廓 73,933 | `build_font.py`、`verify_all.py` |
| 结构一致性 | 通过但**证据薄**：硬检查命中 71（warn 69 / error 2，均为参考集分歧） | `compare_refs.py`、`adversarial_review.py` |
| 视觉平衡 | 通过：整数倍 ppem 下逐格还原；非整数倍下失真 43%（已知边界） | `bitfont.py`、`docs/word-compat.md` §7.6 |
| 回归一致性 | 通过：4,161 字分 43 批，产物与源位图逐像素一致，0 error 0 warn | `regress.py` |
| 对抗式审核 | 通过：三轮命中 60 / 139 / 19，待裁决 0，确认缺陷 0 | `adversarial_review.py` |

## 1. 范围与目的

### 1.1 目的

本文给出 PixelFont 点阵家族**字形本身**的质量判定规范，覆盖四个维度：轮廓完整性、曲线与转角质量、结构一致性、视觉平衡。目标三条：

1. **可复现**：每条判据都绑定仓库内一个可执行脚本或一份报告文件，别人重跑得到同一结论。
2. **可追溯**：每个数字都能指到仓库文件路径 / 命令 / commit / 报告文件。
3. **零主观**：阈值不拍脑袋，按对照集标定；参考集自身的分歧作为噪声底线（详见 2.8）。

本文**不**覆盖：字符集覆盖度、渲染器兼容性、多平台行为、多字号排版——这些属于姊妹篇 SPEC-10《字体测试规格书》。两者术语一致、内容不重复。

### 1.2 适用范围

**在范围内**：字形质量四维（轮廓 / 转角 / 结构 / 视觉平衡）的检查项、量化判据、失败处理、裁决流程；参考集与独立票选取规则；阈值标定方法。

**不在范围内**：字符集规划、多语言版 `PixelFont Multi 12` 的具体实现（尚未开工）、构建流水线本身的正确性（由 `build_font.py` 自检 + `vendor_fusion_pixel.py` 覆盖）。

**版本基线**：本规范的事实基线为 2026-10-24 核实的仓库状态，HEAD `4300fc1`；OS/2 元数据修复对应 commit `cef4a22`。

## 2. 正文

本节把质量检查拆成四层（2.1），逐层给出检查项与判据（2.2–2.5），再给审核流程（2.6）、参考票规则（2.7）、阈值方法（2.8）与已知缺陷（2.9）。所有数字取自统一事实底稿 v2 与仓库内报告，命令见 §4。

### 2.1 质量检查的分层

| 层 | 查什么 | 工具 | 判据类型 |
|---|---|---|---|
| 轮廓层 | 轮廓闭合与绕向、UPM 整除、lsb、`.notdef` 检出、竖向游程合并正确性 | `build_font.py`（`_emit_rect()` / `_merge_vertical_runs()` / `verify_ttf_metadata()`）、fontTools `TTFont` | 二值硬判（通过 / 不通过），不设容差 |
| 结构层 | 结构签名一致性、部件级结构、字形身份 | `route_rule.py::sig_of()`、`compare_refs.py`、`verify_identity.py`、`adversarial_review.py` | 结构签名比对 + 独立参考集对照（**证据薄，见 2.9**） |
| 视觉层 | 墨迹占比、整字集密度、字面框内墨迹重心、连通域数 | `bitfont.py`（`ink_ratio()` / `measure_density()` / `count_holes()`）、`to_ascii()` | 统计量阈值，**阈值按对照集标定**（见 2.8） |
| 回归层 | 产物字形与源位图逐像素一致、产物与 `dist/` 同步 | `regress.py`、`verify_all.py` 第 3 / 5 步 | 逐像素比对，**0 error 0 warn** 才算通过 |

层间关系：轮廓层与回归层是**硬门禁**（任一失败即阻断发布）；结构层与视觉层是**分级门禁**（命中后进入 warn / error 与三态裁决，见 2.6、2.8）。

### 2.2 轮廓完整性检查

前提：点阵字体的轮廓是**每个像素一个矩形**，且 v1.0.0 起竖向相邻、x 范围相同的水平游程**合并成一个矩形**（像素并集不变）。因此轮廓完整性 = "矩形集合的并集必须精确等于设计位图"。

| 编号 | 检查项 | 判据 | 工具 | 失败处理 |
|---|---|---|---|---|
| OUT-01 | `.notdef` 检出 | 参与判定的每个码位在 cmap 中必须映射到**非 `.notdef`** 字形；渲染出空心豆腐框且自带 1 个"字腔"的一律先查 cmap 再下结论 | fontTools `TTFont`（cmap）+ `compare_refs.py` | 阻断：**不得**凭渲染结果判定"某源不可用"（历史上推导名单曾混入 39 个 MS Gothic 根本不存在的码位） |
| OUT-02 | 轮廓闭合 | 每个矩形 4 个控制点闭合，`glyf` 无 open contour | fontTools `glyf` | 阻断，定位到具体码位 |
| OUT-03 | 绕向一致 | 所有矩形同向绕向（non-zero 环绕规则填充），全家族无反向矩形 | `build_font.py::_emit_rect()` | 阻断 |
| OUT-04 | UPM 整除 | `UPM % cell_w == 0`；**768 % 12 == 0**，1 像素 = **64** 单位，误差为 0 | `build_font.py`：`px = UPM // cell_w` | 阻断 |
| OUT-05 | lsb = xMin | 每个字形 `hmtx` 的 lsb 与 `glyf` 的 xMin **完全相等**（差值为 0） | fontTools `hmtx` + `glyf` | 阻断 |
| OUT-06 | 竖向游程合并正确性 | 合并后轮廓数 **73,933**（合并前 107,209，-31%）；像素并集不变 → 整数倍精确性 **12,483 / 12,483** | `build_font.py::_merge_vertical_runs()` + `regress.py` | 阻断；回到未合并路径重验 |
| OUT-07 | 元数据四不变量 | ① 代码页位 = `(1<<0)｜(1<<17)｜(1<<18)`（1252 + 932 + 936）；② `fsSelection` 含 REGULAR（**0x0040**）；③ `ulUnicodeRange1–4` 与 cmap 实际覆盖一致（由 fontTools 重算，**不手写**）；④ `gasp` = `{0xFFFF: 0}`（禁 DOGRAY｜GRIDFIT） | `build_font.py::verify_ttf_metadata()` | 阻断（commit `cef4a22` 修复项，见 `docs/word-compat.md`） |
| OUT-08 | advance 正确 | 半角 **6**、全角 **12** | fontTools `hmtx` | 阻断 |
| OUT-09 | 基线与 cell 高 | ascent **11** / descent **2**，cell 高 **13** | `bitfont.py`：`cell_ascent` / `cell_descent` | 阻断 |

> 说明：OUT-07 的四组不变量对应"Word 里装了却用不上"这一历史根因（旧值 `ulCodePageRange1 = 0x00030000` 实为 bit16 + bit17，既无 1252 也无 936；`fsSelection` 为 0x0000 缺 REGULAR）。

### 2.3 曲线与转角质量

点阵字体**没有曲线**——检查对象不是贝塞尔拟合度，而是**转角的像素化质量**与**端点锐度**：即一个"应该闭合的转角"在 12 × 13 网格里是否仍闭合、一笔是否仍是一笔。可量化的抓手是游程段数、字腔数、墨迹占比，以及在整数倍 / 非整数倍 ppem 下的连通性表现。

| 编号 | 检查项 | 判据 | 工具 |
|---|---|---|---|
| TURN-01 | 竖笔分段（纵向游程段数） | 与独立参考集在同一 ppem 下的分段数分布比较；超出对照集分歧范围才判命中 | `bitfont.py::count_runs(img, axis='col')` |
| TURN-02 | 横笔分段（横向游程段数） | 同上 | `bitfont.py::count_runs(img, axis='row')` |
| TURN-03 | 字腔数 | 与参考集同判据比较；**注意 `.notdef` 自带 1 个字腔**，判"字腔多一个"前必须先查 cmap | `bitfont.py::count_holes(img)` |
| TURN-04 | 端点锐度 / 断笔 | 12 的整数倍 ppem（12 / 24 / 36ppem @96dpi）下全字符集逐格还原；非整数倍（18ppem = 1.5 倍）下墨迹量偏细 **43%** 属**已知失真**，不计为缺陷 | `verify_gdi.py`、`docs/word-compat.md` §7.2 / §7.6 |
| TURN-05 | 转角像素化人工复核 | 逐字把 12 × 13 位图打成 ASCII 文本，人工确认转角闭合与笔画数 | `bitfont.py::to_ascii(img, ink='#', paper='.')` |
| TURN-06 | 合并后像素并集不变 | 合并竖向游程前后，同一码位在同一 ppem 下渲染结果逐像素相同（整数倍精确性 **12,483 / 12,483**） | `regress.py` + `verify_all.py` 第 3 步 |
| TURN-07 | 单向游程阈值档位 | 结构距离**绝对差 ≥ 12** 档位在 Ark ↔ Fusion 简体 3,605 共有汉字上的占比为 **0.0%**；**中间档位（绝对差 ∈ [1, 11]）阈值待验证** —— 验证方法：以参考集自身分歧分布为噪声底线，用 `compare_refs.py` 复算并取分位点 | `compare_refs.py`、`route_rule.py::sig_of()` |

> 为什么合并竖向游程是"转角质量"的一部分：非整数倍缩放下每个矩形**独立**吸附到输出网格，1.5px 的方块有的落进 1 格、有的整个落空，笔画就断成虚线。合并把同一竖笔变成一个长矩形，吸附行为一致，断笔风险随之下降（详见 `docs/word-compat.md`）。

### 2.4 结构一致性检查

| 编号 | 检查项 | 判据 | 工具 |
|---|---|---|---|
| SIG-01 | 结构签名定义 | `sig_of()` 输出 = **字腔数 / 竖笔分段 / 横笔分段**；字腔数取自 `count_holes()`，竖笔 / 横笔分段取自 `count_runs()` 的两个轴向（**轴向对应关系待验证**：验证方法 = 读 `route_rule.py::sig_of()` 实现确认 col / row 分别对应哪一项） | `route_rule.py::sig_of()` |
| SIG-02 | 结构签名比对方式 | 逐字与**独立**参考集比对；命中阈值按 2.8 标定；**结构签名一致不等于字形相同**，只作线索 | `compare_refs.py`（539 行） |
| SIG-03 | 部件级结构比对 | 拆到笔画 / 部件层比对，识别"结构张冠李戴"（对抗审核第 2 轮，产出记为命中） | `adversarial_review.py` |
| SIG-04 | 字形身份校验 | 从位图**反查**它是不是某个已知字，而不是从码位正向相信它；身份不符即命中 | `verify_identity.py` |
| SIG-05 | 独立票选取规则 | 与生产源**无谱系依赖**才算独立票；生产源自家上游不计票（见 2.7） | 本文 §2.7 规则表 |
| SIG-06 | 结构判据的证据强度 | 12px 层面独立票仅 **2** 张（Zpix / Unifont），结构结论必须与 TURN / VIS 判据合看，**不得单票否决** | 本文 §2.9 |

### 2.5 视觉平衡检查

| 编号 | 检查项 | 判据 | 工具 |
|---|---|---|---|
| VIS-01 | 单字墨迹占比 | 逐字 `ink_ratio(img)`；与同类别参考字比较，离群才判命中；**单字绝对阈值待验证** —— 验证方法：用 `compare_refs.py` 的参考集墨迹占比分布取分位点标定（与 2.8 方法一致） | `bitfont.py::ink_ratio(img)` |
| VIS-02 | 整字集密度 | `measure_density(font)` 输出全字集密度，作为版本间横向对比基线 | `bitfont.py::measure_density(font)` |
| VIS-03 | 字面框内墨迹重心 | 以字面框 / advance 为基准计算墨迹重心偏移；**偏移上限百分比待验证** —— 验证方法：先在参考集上测出重心偏移分布，再取其高分位作为阈值 | `bitfont.py`（与 `ink_ratio` 同一套像素遍历接口） |
| VIS-04 | 连通域数 | 整数倍 ppem 下连通域应与设计位图一致；非整数倍下连通域变化属已知失真（`中` @18ppem 连通域 **8 → 3**），仅作记录不计缺陷 | 位图连通域统计（`bitfont.py` 像素遍历） |
| VIS-05 | 字面宽度与 advance 一致 | 半角 advance **6** / 全角 **12**，墨迹不越出各自字面框 | fontTools `hmtx` + 位图边界 |
| VIS-06 | 视觉复核抽样 | 用 `to_ascii()` 输出 ASCII 位图，按 §2.3 TURN-05 流程做人工复核；抽样口径 **待验证** —— 验证方法：由 `adversarial_review.py` 的抽样实现或门禁配置给出实际口径 | `bitfont.py::to_ascii()` |

### 2.6 对抗式审核规范

`tools/fontgen/adversarial_review.py`（1,586 行）跑三轮互相独立的攻击面，产出**命中**列表；命中不等于缺陷，必须进入三态裁决。

| 轮次 | 攻击面 | 方法 | 输出 |
|---|---|---|---|
| 1 | 身份反查 | 从位图反查它是不是某个已知字，而不是从码位正向相信它 | 命中条目（含码位、证据位图、判据） |
| 2 | 部件级结构 | 拆到笔画 / 部件层比对，识别"结构张冠李戴" | 命中条目（部件级差异描述） |
| 3 | 链条 | 检查从源位图到成品字形整条链路上有没有掉字、串字、错位 | 命中条目（链路环节定位） |

三态裁决流程（每个命中必须落到且只落到一个状态）：

| 状态 | 含义 | 出口 |
|---|---|---|
| 待裁决 | 命中但尚未定性 | 必须裁决；**待裁决不为 0 才算流程走完** |
| 已裁决非缺陷 | 经复核判定为参考集分歧 / 误报 | 记入裁决台账，不计缺陷 |
| 确认缺陷 | 确认为真实字形缺陷 | 进入修复流程，修复后重跑全部门禁 |

最近一次全量结果：三轮命中 **60 / 139 / 19**，**待裁决 0**，已裁决非缺陷 **169**，**确认缺陷 0**。

### 2.7 参考集与独立票规则

| 字体 | 许可证 | 谱系 | 是否独立票 | 是否参与 12px 笔画数比对 | 自身缺字数 |
|---|---|---|---|---|---|
| Ark Pixel 12px | OFL-1.1 | **Fusion 上游** | **否**（简体版 3,605 个共有汉字结构签名逐个完全相同：结构距离均值 **0.00**、中位 **0.0**、绝对差 ≥ 12 占比 **0.0%**） | 是（但自证） | **150**（GB2312 后半的简体字） |
| Fusion Pixel 12px（ja / ko / latin / zh_hans / zh_hant / zh_hk / zh_tw 七变体） | OFL-1.1 | 生产源本家 | **否**（生产源自证） | 是 | 待验证 —— 验证方法：fontTools 读七变体 cmap，与本项目字符集求差并逐变体计数 |
| Zpix（最像素）v3.3.0 | MIT | 与生产源独立 | **是** | 是 | **12**（`U+3094-3096`、`U+3099`、`U+309A`、`U+309F`、`U+30A0`、`U+30F7-30FF` 等假名） |
| GNU Unifont 16.0.01 | GPL-2.0+（含字体嵌入例外） | 非 CJK 谱系 | **是** | **否**（16 × 16 网格，不参与 12px 笔画数比对） | 待验证 —— 验证方法：fontTools 读 Unifont cmap 与本项目字符集求差 |
| SimHei | 微软专有 | 汉字生产源 | 不适用（生产源） | 不适用 | 不适用 |
| MS Gothic | 微软专有 | 拉丁 / 假名生产源 | 不适用（生产源） | 不适用 | 不适用 |

规则三条：

1. **独立性优先于丰富度**：与生产源同谱系的字体（如 Ark vs Fusion）即便覆盖更多汉字也不计票，因为它们的结构签名天然一致，提供不了区分度。
2. **票数 = 2 是当前上限**：12px 层面可用的票只有 **Zpix**（MIT）+ **Unifont**（GPL-2.0+）两张，而 Unifont 因 16 × 16 网格**不参与 12px 笔画数比对** → 笔画数比对实际可用票只有 Zpix。目视复核的参考列因此已改为 **Zpix + Unifont**。
3. **参考字体自身缺字是参考字体的属性，不是本项目的缺陷**：报告中**单列、不参与判定**（Ark 缺 150、Zpix 缺 12）。

来源、版本与 sha256 清单见 `docs/reference-fonts.md`；抓取脚本 `tools/fontgen/fetch_ref_fonts.py`（`--verify` 只校验不重下）。

### 2.8 阈值标定与误报控制

| 项 | 规则 |
|---|---|
| 阈值来源 | **按对照集标定**，不是拍脑袋定数字。方法：把生产源与独立参考集在同一 ppem 下渲染，比较结构签名分布 |
| 噪声底线 | **参考集自身的分歧**即噪声底线；生产源与参考集的差异若不超过该底线，不判命中 |
| 档位示例 | 结构距离**绝对差 ≥ 12** 档位：Ark ↔ Fusion 简体 3,605 共有汉字上占比 **0.0%**（自证族的直接证据） |
| 参考集缺字 | 参考字体自身缺字**单列**，不参与判定、不计缺陷（Ark 150 / Zpix 12） |
| `.notdef` 防御 | FreeType 会把缺字画成空心豆腐框（自带 **1** 个"字腔"）；判定"某个源行不行"必须**先查 cmap**，不能靠渲染结果猜 |
| 命中分级 | 硬检查命中分 warn / error；最近一次命中 **71** = **warn 69 / error 2**，**两者均为参考集分歧**，非确认缺陷 |
| 流程门禁 | 待裁决必须为 **0**；确认缺陷必须为 **0**；回归必须 **0 error 0 warn** |
| 判定保守原则 | 证据薄的结构层结论（独立票仅 2 张）不得单独否决发布，需与轮廓层 / 回归层判据合看 |
