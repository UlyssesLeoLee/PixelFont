# 02. 字符集定义书

> 适用对象：`PixelFont PC98 12`（已发布 v1.0.0）与规划中的 `PixelFont Multi 12`
> 事实底稿日期：2026-10-24
> 相关文档：`01-font-design-requirements.md`（需求规格）、`08-font-production-design.md`（构建流程）、`docs/word-compat.md`（渲染实测）

## 结论先行

**本项目的字符集是"机械推导"出来的，不是列出来的。** 任何汉字表只要是凭记忆写的，就是编造 —— 所以 GB2312 一级汉字用**区位码区间**推导，JIS X 0208 汉字用**Shift-JIS 双字节判定**推导，两者都不靠人列。

**当前家族 `PixelFont PC98 12` 覆盖 4,161 码位**，分四类且四类之和恰等于总数：

| 类别 | 码位 | 推导方式 |
|---|---|---|
| ASCII | 95 | `U+0020`–`U+007E` 连续区间 |
| 标点与符号 | 56 | `charset.extras()` 显式枚举 |
| 假名 | 255 | 假名区间 + 表外记号，去重后 |
| 汉字 | 3,755 | GB2312 一级（区位 16–55 区）机械推导 |
| **合计** | **4,161** | |

**多语言版 `PixelFont Multi 12` 目标 31,392 码位**（方案 C = 方案 A + 全部 CJK），逐层增量可加总复核：4,161 → 4,402 → 4,501 → 4,652 → 15,824 → 17,519 → 19,816 → **31,392**。

**中日共享的 2,078 个汉字里，有 434 个（20.9%）在日文源与中文源之间字形不同** —— 这是"中日共享字取中文形"的唯一硬依据，不是审美偏好。

**明确的四类边界**（如实写，不夸大）：① 阿拉伯、希伯来、天城文、泰文**不覆盖** —— 只有 Unifont 16 的 16×16 点阵，塞不进 12px 格；② `€ ≠ ≤ ≥` 这 4 个码位**不被任何 Fusion 变体覆盖**，必须走 MS Gothic / SimHei 路径；③ `U+3097 ゗` `U+3098 ゘` **被排除**（古旧假名合字，非 JIS 字集）；④ `U+005C` **有源例外**（MS Gothic 按 JIS 惯例把它画成 `¥`）。

## 1. 范围与目的

### 1.1 目的

本文是 PixelFont 项目 12 份设计规格文档中的第 2 份，负责定义**收哪些字符、怎么收、为什么这么收、以及哪些明确不收**。

| 问题 | 本文回答 |
|---|---|
| 收录范围 | 当前家族 4,161 码位与多语言版 31,392 码位分别由什么构成、逐项怎么算出来 |
| 收录规则 | 机械推导优先；显式枚举只用于符号类；每条规则都能被脚本复算 |
| 优先级 | 总量受限时按什么顺序取舍 |
| 缺字策略 | 缺字时渲染成什么、怎么被门禁拦住 |
| 边界 | 哪些语系不覆盖、哪些码位被排除或走特殊源 |

### 1.2 适用范围

- **在范围内**：`PixelFont PC98 12` v1.0.0 的字符集构成与规则；`PixelFont Multi 12` 的目标集合定义与逐层账目。
- **不在范围内**：字形美术设计（见 `03` / `04`）、构建实现细节（见 `08`）、渲染兼容性的根因分析（见 `docs/word-compat.md`）、成品再分发的授权判定（见 `12`）。

### 1.3 读者

| 读者 | 关心什么 |
|---|---|
| 维护者 | 改字符集时哪些能改、哪些会被门禁拦下 |
| 实现者 | 多语言版要凑够 31,392 码位，从哪些源取 |
| 审阅者 | 这份清单是推导出来的还是编出来的 |

### 1.4 术语

- **码位**（code point）= Unicode 标量值，本文一律写作 `U+XXXX`。
- **机械推导** = 由区间规则或编码判定算出集合，不经人工列举。
- **源例外**（source override）= 某码位不走默认选源结果，改走指定字体。
- **全角 / 半角** = 本字体中 advance 为 12 / 6 的字符格。
- **独立票** = 与生产源谱系无关、可当"这个字本来就该长这样"基准的参考字体。

## 2. 正文

### 2.1 字符集总览

项目有两个字符集目标：

| 集合 | 码位 | 状态 | 家族 |
|---|---|---|---|
| 当前家族字符集 | **4,161** | 已发布（v1.0.0） | `PixelFont PC98 12` |
| 多语言版目标字符集 | **31,392** | 计划中，**尚未开工** | `PixelFont Multi 12`（独立家族） |

两者**不共享同一套编号规则**：`PixelFont Multi 12` 是**新增的独立家族**，不是现有家族的字符集扩展 —— 现有家族不加一字。

### 2.2 当前家族字符集的构成

#### 2.2.1 四类合计

| 类别 | 码位 | 来源 | 定义位置 |
|---|---|---|---|
| ASCII | 95 | `U+0020`–`U+007E` | `charset.ascii_chars()` |
| 标点与符号 | 56 | 显式枚举 | `charset.extras()` |
| 假名 | 255 | 假名区间 + 表外记号 | `charset.kana_chars()` |
| 汉字 | 3,755 | GB2312 一级机械推导 | `charset.gb2312_level1()` |
| **合计** | **4,161** | — | `charset.build_charset()` |

#### 2.2.2 去重：为什么源列表是 4,164 而结果是 4,161

四个源函数直接相加是 **4,164**，去重后 **4,161**，差 3：

| 重复字符 | 码位 | 重复来源 |
|---|---|---|
| `ヶ` | `U+30F6` | 假名表 + 符号表 |
| `ー` | `U+30FC` | 假名表 + 符号表 |
| `～` | `U+FF5E` | 假名表 + 符号表 |

对应地，`kana_chars()` 返回 **258** 个去重后的假名字符，其中 3 个同时出现在 `extras()` 里，所以最终计入假名类的净增是 **255**。

> 判据：`charset.build_charset()` 的返回值长度必须等于 4,161，且 `len(set(...))` 也等于 4,161 —— 返回值本身无重复。

#### 2.2.3 汉字集：GB2312 一级是推导出来的

| 项 | 值 |
|---|---|
| 推导依据 | GB2312 **区位 16–55 区** |
| GB2312 字节码范围 | `0xB0A1`–`0xD7F9` |
| 对应 Unicode 范围 | `U+554A`（啊）– `U+5EA7`（座） |
| 字数 | **3,755** |

40 区 × 94 字 = 3,760，其中 5 个为未定义码位，故实得 3,755。

**为什么必须机械推导**：GB2312 一级汉字有三千多字，任何人凭记忆列表都会漏字、错字、重复。而 GB2312 的编码本身就是一张完整的表 —— 按码位区间取，得到的集合**可被任何人用一条脚本复现**。

#### 2.2.4 假名集：区间 + 表外记号

`charset.kana_chars()` 返回 **258** 个去重后的字符，覆盖：

| 组 | 范围 / 内容 |
|---|---|
| 平假名 | `U+3041`–`U+309F` |
| 片假名 | `U+30A0`–`U+30FF` |
| 半角片假名 | `U+FF61`–`U+FF9F` |
| 迭代记号等表外字符 | `々 〆 〇`、`ゔ ゕ ゖ`、`゙ ゚ ゛ ゜`、`ゝ ゞ ゟ ゠`、`ヷ ヸ ヹ ヺ`、`ヽ ヾ ヿ`、`・ ー`、`～`、浊点/半浊点组合 `ﾞ ﾟ` |

#### 2.2.5 标点与符号集：56 个的完整清单

| 组 | 字符 | 个数 |
|---|---|---|
| 基础标点 | `、。，．！？；：（）【】「」『』《》〈〉` | 20 |
| 连接 / 省略 / 减号 / 加号 | `· — … ～ － ＋` | 6 |
| 数学与百分比 | `× ÷ ＝ ％` | 4 |
| 货币与记号 | `＄ ￥ ＃ ＆ ＠ ¥ ° ½` | 7 |
| 引号 | `“ ” ‘ ’` | 4 |
| 箭头与不等号 | `– • ‧ € → ≠ ≤ ≥` | 8 |
| 括号补充 | `［ ］ ｛ ｝` | 4 |
| 空白 | NBSP `U+00A0`、全角空格 `U+3000` | 2 |
| **合计** | — | **56** |

#### 2.2.6 2026-10-24 补入的 21 个字符

commit `729403c` 一次性补入 21 个 Word 常用字符，把字符集从 **4,140 扩到 4,161**：

| 组 | 字符 | 个数 |
|---|---|---|
| 弯引号 | `“ ” ‘ ’` | 4 |
| 全角空格 | `U+3000` | 1 |
| 不换行空格 | `U+00A0` | 1 |
| 短横 / 圆点 / 双点 | `– • ‧` | 3 |
| 日元 / 度 / 二分之一 | `¥ ° ½` | 3 |
| 欧元 / 箭头 | `€ →` | 2 |
| 不等号 | `≠ ≤ ≥` | 3 |
| 全角括号 | `［ ］ ｛ ｝` | 4 |
| **合计** | — | **21** |

同一次改动还修掉一个真缺陷：`U+005C` 反斜杠 —— MS Gothic 按 **JIS 惯例**把 `U+005C` 画成 `¥`，导致它与 `U+00A5` 的整格位图**逐字节相同**。详见 §2.6。

### 2.3 收录原则

| 编号 | 原则 | 可判定性 |
|---|---|---|
| P1 | **机械推导优先**：能用区间 / 编码判定算出来的，绝不人工列举 | 可用一条脚本复算出完全相同的集合 |
| P2 | 显式枚举只用于**符号类**（ASCII 之外的标点、记号） | 清单长度与代码一一对应 |
| P3 | 汉字集必须落在**已知标准字集**内（GB2312 / JIS X 0208 / Unicode CJK 区），不得自造 | 每字都能在标准字集里查到 |
| P4 | 每一类都必须能说出**它的选源结果**（哪个源出这个字形） | 选源失败即缺字，门禁报错 |
| P5 | 排除必须有**理由**，且理由要可被独立复核 | 见 §2.5 |
| P6 | 总量变化必须能**逐层加总复核** | 见 §2.7 |

### 2.4 源选择规则

字符集定义"收什么"，源选择定义"这个字从哪来"。两者由 `charset.build_stack()` + `bitfont.ScriptStack` 串起来。

| 类别 | 默认源 | 说明 |
|---|---|---|
| 汉字 | `ideo_route.json` 路由名单（**3,010 条**） | 逐字选源，不是"整个语系一个源" |
| 拉丁 / 假名 | MS Gothic | `C:\Windows\Fonts\msgothic.ttc` |
| 汉字兜底 | SimHei | `C:\Windows\Fonts\simhei.ttf` |
| 第三源 | Fusion Pixel 12px 简体裁剪版 | `vendor/fusion-pixel-12px/fusion-pixel-12px-monospaced-zh_hans-subset.ttf`（**764,748 字节**，sha256 `FC910F23FF8EE2DF8F2FEC6F91381A60DF812E3A16CE177F48528F1DB6551A37`） |

路由名单由 `derive_ideo_route.py` 推导、`route_rule.py::sig_of()` 判定，规则按 `route_rule.py` 的公共模块计算，**不重复实现**（历史上 `explain_route` 与构建结果打架过，已由 commit `13e1952` 修正）。

### 2.5 排除规则

`charset.EXCLUDE` 当前只有 2 项：

| 码位 | 字符 | 排除理由 |
|---|---|---|
| `U+3097` | `゗` | 古旧假名合字，**非 JIS 字集**，MS Gothic 无此字形 |
| `U+3098` | `゘` | 同上 |

判据是**源里根本没有** —— 不是"我们不想要"，是"源画不出"。若将来引入能画这两个字的源，应重新评估。

### 2.6 源例外规则

`charset.SOURCE_OVERRIDES` 当前只有 1 项：

| 码位 | 字符 | 默认源的问题 | 例外动作 |
|---|---|---|---|
| `U+005C` | `\` | MS Gothic 按 **JIS 惯例**把 `U+005C` 画成 `¥`，与 `U+00A5` 整格位图**逐字节相同** | 切到 Fusion Pixel |

配套机制：`bitfont.ScriptStack` 的 **`overrides` 参数**是这类"源字体语系惯例"问题的**专用通道**；`ideo_route.json` 只管汉字，不管这类问题 —— 两者不能混用。

### 2.7 多语言版目标集合：逐层账目

方案 C = 方案 A（L0–L6）+ 全部 CJK（L7）。每一层的增量都是「实际字体 cmap 的交集」，不是理论块大小：

| 层 | 内容 | 增量 | 累计 |
|---|---|---|---|
| L0 | 当前家族 | 4,161 | 4,161 |
| L1 | + Latin Ext A/B（`U+0100`–`U+024F` ∩ Fusion latin） | 241 | 4,402 |
| L2 | + Greek（`U+0370`–`U+03FF` ∩ Fusion latin） | 99 | 4,501 |
| L3 | + Cyrillic（`U+0400`–`U+04FF` ∩ Fusion latin） | 151 | 4,652 |
| L4 | + Hangul syllables（`U+AC00`–`U+D7AF` ∩ Fusion ko） | 11,172 | 15,824 |
| L5 | + JIS X 0208 假名 / 符号 / 全角（Shift-JIS 首字节 `0x81`–`0x87`、`0xE0`–`0xEF` ∩ Fusion ja） | 1,695 | 17,519 |
| L6 | + JIS X 0208 汉字 4,375（Shift-JIS 首字节 `0x88`–`0x9F` ∩ Fusion ja） | 2,297 | 19,816 |
| L7 | + CJK 其余（`U+4E00`–`U+9FFF` ∩ Fusion ja） | 11,576 | **31,392** |

**交叉核对**（两条独立算法必须给出同一个数）：

| 口径 | 值 |
|---|---|
| 方案 A（L0–L6） | **19,816** |
| CJK 整块 `U+4E00`–`U+9FFF` ∩ Fusion ja | **19,317** |
| 方案 C = A ∪ CJK | **31,392** |
| 逐层累加 L0–L7 | **31,392** ✔ 一致 |

> 注意 19,317 与 Unicode CJK 整块 20,991 的差额：Fusion ja 的 cmap **不覆盖** CJK 整块里的全部码位，所以交集是 19,317 而非 20,991。这个差额不是错误。

### 2.8 中日汉字重叠与字形分歧

#### 2.8.1 重叠结构（机械推导）

| 项 | 数量 | 推导方式 |
|---|---|---|
| GB2312 一级汉字 | 3,755 | 区位 16–55 区 |
| JIS X 0208 汉字 | 4,375 | Shift-JIS 双字节，首字节 `0x88`–`0x9F` |
| **交集（中日共享）** | **2,078** | 两者求交 |
| JIS 独有 | 2,297 | JIS − GB2312 |
| GB 独有 | 1,677 | GB2312 − JIS |

#### 2.8.2 源覆盖：无一遗漏

| 集合 | Fusion ja 覆盖 | Fusion zh_hans 覆盖 |
|---|---|---|
| 中日共享 2,078 | 2,078 / 2,078 | 2,078 / 2,078 |
| JIS 独有 2,297 | 2,297 / 2,297 | — |
| GB 独有 1,677 | 1,677 / 1,677 | — |

且 ja 与 zh 在共享集上的**码位集合完全相同**（对称差为 0）。JIS 独有 2,297 字在 Fusion ja 源中渲染 **2,297 / 2,297 全部有墨迹**，不缺字。

| `U+904D` | 遍 | 59 | `U+6241` | 扁 | 54 |

#### 2.8.4 由此确定的取形策略

**中日共享 2,078 字取中文形（zh_hans 源），JIS 独有 2,297 字走 ja 源。**

| 理由 | 依据 |
|---|---|
| 分歧真实存在，不是理论顾虑 | 434 / 2,078 像素级不同（§2.8.3） |
| 共享字默认中文形对多数用户是正确的 | `PixelFont Multi 12` 的主用途是中文正文 |
| JIS 独有字只有 ja 源有 | ja 覆盖 2,297 / 2,297（§2.8.2） |
| 不引入 GSUB `locl` 变体 | 变体机制需要字形映射表与 `GSUB`/`GPOS` 基础设施，架构改动过大，**已评估后未选** |

**代价与未决**：共享字若要日式字形，当前**没有切换机制**（无 `locl`）。这是明确的能力缺口，不是遗漏。

### 2.9 覆盖缺口

Fusion 七个变体（ja / ko / latin / zh_hans / zh_hant / zh_hk / zh_tw）的 cmap 并集为 **37,415** 码位。方案 C 的 31,392 中有 **4 个码位不被任何 Fusion 变体覆盖**：

| 码位 | 字符 | 当前家族 | 说明 |
|---|---|---|---|
| `U+20AC` | `€` | 已有 | 走 MS Gothic / SimHei 路径 |
| `U+2260` | `≠` | 已有 | 同上 |
| `U+2264` | `≤` | 已有 | 同上 |
| `U+2265` | `≥` | 已有 | 同上 |

这 4 个与 `docs/reference-fonts.md` 记载的「Fusion 覆盖 4,157 / 4,161，缺的 4 个是 `€ ≠ ≤ ≥`」**完全一致**，互为交叉验证。多语言版须沿用同样的非第三源路径。

### 2.10 明确不覆盖的语系

| 语系 | 码位范围 | Unifont 16 可覆盖数 | 为何不纳入 |
|---|---|---|---|
| 希伯来 | `U+0590`–`U+05FF` | 112 | Unifont 是 **16×16** 网格，塞不进 12px 格 |
| 阿拉伯 | `U+0600`–`U+06FF` | 256 | 同上（且阿拉伯字形有连写与字形替换，非单字符栅格） |
| 天城文 | `U+0900`–`U+097F` | 128 | 同上（天城文有合体字与上下标结构） |
| 泰文 | `U+0E00`–`U+0E7F` | 128 | 同上（泰文有基线堆叠与前置元音） |
| 谚文字母 | `U+1100`–`U+11FF` | 256 | 谚文音节（`U+AC00`–`U+D7AF`）已通过 Fusion ko 覆盖；字母区仅作补充 |

这 5 项合计 **880** 个码位，构成"方案 B"（A + Unifont 16 六语系）的增量。方案 B 实测为 **20,712 码位**（较方案 A +896）。**方案 C 不含这 896**。

> 判别口径：像素字体的可移植性由**栅格尺寸**决定，不由 Unicode 覆盖面决定。16×16 的点阵缩到 12px 格会破坏其笔画结构 —— 这不是取舍偏好，是物理约束。

### 2.11 缺字策略

| 项 | 规则 |
|---|---|
| 缺字字形 | `.notdef` = **空心方框**（双层矩形环），上沿到基线上方 `ascent` 处、下沿伸到基线下方 `descent` 处 |
| 为什么不用 y=0 起画 | 缺字框会比真实字面高一截，排版时明显错位 |
| 缺字可见性 | 豆腐框是**故意**的 —— 缺字必须肉眼可见，不能静默渲染成空白 |
| 构建期拦截 | `charset.gate_full_coverage()` 拦缺字；`charset.gate_ideo_route()` 拦路由名单不一致 |
| 覆盖校验 | 产物与源位图逐像素比对由 `regress.py` 承担（4,161 字分 **43 批**） |

### 2.12 优先级规则（总量受限时如何取舍）

若将来出现体积上限或授权限制导致必须砍码位，取舍顺序为：

| 优先级 | 类别 | 理由 |
|---|---|---|
| P1（最后砍） | ASCII 95 | 一切文本的基础 |
| P1 | 汉字（GB2312 一级 3,755） | 中文正文的最小可用集 |
| P2 | 假名 255 | 日文正文 |
| P3 | 标点与符号 56 | 排版必需，但可用其它字体补 |
| P4 | Hangul syllables 11,172 | 单项体积最大的块；若需腾空间，整块先移出 |
| P5 | JIS 独有 2,297 | 覆盖面广但使用频率低 |
| P6（先砍） | CJK 其余 11,576 | 大盘补全，字频低 |

砍任何一类都必须**同时更新**本表的账目，并在版本记录里按 `11-version-and-change-management.md` 的规则登记。
