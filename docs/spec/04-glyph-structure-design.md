## 结论先行

点阵字形的构造原则只有一条能落地：**像素是构造基元，不是采样结果**。本项目的字形不是"先画矢量、再栅格化到 12px"，而是直接在 12 × 13 的网格上以「1 像素宽笔画」为唯一积木拼装——因此所有构造规则最终都必须能回答"这个像素亮不亮"，而不是"这条曲线长什么样"。落到规格上，它压成四条硬约束：em 方框按**字宽 12** 取（不按 cell 高 13）、1 像素 = 64 单位（UPM 768）、advance 半角 6 / 全角 12、ascent 11 / descent 2。这四条若错，后面所有努力都作废——按 13 除会让 12ppem 下每像素落在 0.923 个设备像素上，整副字糊掉。

部件复用在本品类里**只能做到"逐像素等价"这一档**。矢量字体复用部件可以接受"形状大致相似、尺寸缩放即可"；12px 网格下"大致相似"会直接变成肉眼可见的偏心、错位或断裂，所以复用的判据必须是逐位图相同，或者至少结构签名（`route_rule.py::sig_of()`）等价且经 `count_runs()` / `count_holes()` / `ink_ratio()` 量化对齐。把"部件是否一致"从目视问题变成可计算问题，是本品类部件复用的唯一可行路径。

真正的"构造规则"里，有三类是**可机器判定的硬约束**，不需要人眼：① 度量约束（em/UPM/advance/ascent/descent，构建期常量）；② 墨迹框约束（hmtx 的 lsb 必须等于 glyf 的 xMin，即墨迹左边缘，不等则渲染器整字平移）；③ 笔画约束（笔画恒为 1 像素宽、横竖等粗、方笔无衬线、竖向游程合并）。`verify_all.py` 的 8 步验收正是围绕这三类搭建的，最近一次 8/8 PASS，回归 0 error 0 warn，对抗式审核三轮命中 60 / 139 / 19、待裁决 0、已裁决非缺陷 169、**确认缺陷 0**。

必须诚实写出的边界：**构造规则只保证 12 的整数倍字号逐格还原**。18ppem（1.5 倍非整数缩放）下仍有 590/595 字发生连通性变化，墨迹量偏细 43%；这不是字形结构缺陷，而是渲染期缩放语义问题，文档只能承诺 12 / 24 / 36ppem @96dpi。中日共享汉字里 434 / 2,078 在 Fusion ja 与 zh_hans 源之间像素不同（约 21%），当前策略是"中文形为主 + JIS 独有 2,297 字走 ja 源"，`locl` 变体因架构改动过大未选——所以中日两语用户拿到的是同一副中文形，这一点写在这里，不留给用户自己发现。

## 1. 范围与目的

### 1.1 目的

本文规定 `PixelFont PC98 12`（及规划中的 `PixelFont Multi 12`）**字形是怎么搭出来的**，把"好看"这种不可验收的描述，转写为可验收的构造规则：

1. 给出设计网格与度量的**唯一口径**（比例、em、advance、基线）。
2. 给出**字面框与墨迹框**的对齐口径（lsb / xMin）。
3. 给出**笔画的像素化规则**（端点、拐角、粗细、无衬线）。
4. 给出**部件复用**在本品类下的可行边界与量化判据。
5. 给出**笔画交接与连通性**的判定口径与诚实边界。
6. 给出**结构一致性门禁**（哪些检查是硬拦、哪些是告警）。
7. 给出**中日共享字形**与**多语言扩展**在构造层的要求。

## 2. 正文

### 2.1 字形比例与网格

| 项 | 值 | 说明 |
|---|---|---|
| 设计网格 | **12 × 13 像素**（宽 × 高） | 12px 等宽，PC-98 风格；每个 cell 是一个字符的构造画布 |
| em 方框口径 | 按**字宽 12** 取，**不是** cell 高 13 | 早期按 13 除会让 12ppem 下每像素落在 **0.923** 个设备像素上，整副字糊掉 |
| UPM | **768** | 768 = 12 × 64 |
| 1 像素 | **64 单位** | `px = UPM // cell_w` = 768 // 12 = 64 |
| advance（半角） | **6** px = 384 单位 | 12px 格内占半格 |
| advance（全角） | **12** px = 768 单位 | 整格 |
| ascent | **11** px = 704 单位 | 基线在第 11 行下方 |
| descent | **2** px = 128 单位 | cell 第 12 行 |
| cell 高 | **13** px = 832 单位 | ascent + descent = 11 + 2 = 13 |
| 可逐格还原的字号 | 12ppem（= 9pt）、24ppem（= 18pt）、36ppem（= 27pt）@96dpi | 只有 **12 的整数倍**能逐格还原设计 |
| 比例推导链 | cell_w = 12 → em = 12 px → UPM = 768 → 1 px = 64 单位 | 四个值互相锁定，改一个必须改其余三个 |
| 源码 | `tools/fontgen/build_font.py`（`UPM`、`px = UPM // cell_w`、`_emit_rect()`、`_merge_vertical_runs()`）；`tools/fontgen/bitfont.py`（`cell_ascent` / `cell_descent`） | — |

> 判定：若某处出现 `UPM // 13` 或 em 取 13 的写法，视为**破坏性缺陷**——它不改变任何字形的"形状"，却让整副字在 12ppem 下不可读。这条是构建期常量级硬拦（§3 AC-01）。

### 2.2 字面框与墨迹框

| 项 | 值 | 依据 |
|---|---|---|
| 全角字面框 | **12** px | 设计网格宽 = 12；advance 全角 = 12 |
| 半角字面框 | **6** px | advance 半角 = 6 |
| lsb 的正确口径 | hmtx 的 **lsb 必须等于 glyf 的 xMin**（即墨迹左边缘） | lsb 是 xMin 的度量副本；不等意味着渲染器按 lsb 定位而墨迹本身在别处，整字被平移 |
| 窄字形墨迹起点 | `!` U+0021、`'` U+0027、`(` U+0028、`)` U+0029、`,` U+002C 的墨迹**不从 x=0 开始**（xMin ≥ 1） | 若 lsb 填 0，渲染器会把这些标点**整体左移 1–3 像素**，越出字面框并与相邻字重叠 |
| 墨迹框纵向边界 | 墨迹不得越过 ascent（y = 11px）与 descent（y = −2px） | 越界 = 上下相邻行裁切 |
| 墨迹框横向边界 | 半角字墨迹须落在 [0, 6]，全角字落在 [0, 12] | 越界 = 与邻字碰撞 |
| 全角标点的 lsb | 不因"标点在视觉上居左"而填 0 | 标点字面框宽仍是 12；居左是设计选择，lsb 仍等于 xMin |
| 半角标点的对齐 | lsb = xMin（可能为 1–5），不做"视觉居中"补偿 | 居中补偿会破坏与相邻拉丁字母的光学对齐，且不可预测 |

> 判定：lsb ≠ xMin 的字形不是"偏移一点"，是**渲染期整体平移**。窄字形（标点、括号、逗号）最容易踩这个坑——它们墨迹窄，一旦 lsb 填 0，左移量 1–3 像素在 12px 格内是肉眼可见的错位。

### 2.3 笔画构造规则

| 规则 | 判定 | 实现 |
|---|---|---|
| 笔画恒为 **1 像素宽** | 任一水平/竖直游程的长度 = 1；无 2px 及以上宽笔画 | 构造时直接按 1px 落笔；`count_runs()` 可逐行扫描复核 |
| 横竖**等粗** | 同一字形内横笔与竖笔的游程长度一致；不做横细竖粗的对比调整 | 等宽栅格的必然结果：12px 内做粗细对比只剩 1px 差，横竖无法同时取两种宽度 |
| **方笔无衬线** | 笔画端点为直角，无圆角、无斜切、无衬线伸出 | 轮廓只由轴对齐矩形构成；TrueType 坐标系 y 向上，所有矩形**同向绕向**，non-zero 环绕规则填充 |
| **端点像素化** | 笔画端点必须落在整像素网格线上，不允许半像素起点/终点 | 1px = 64 单位，网格线在整数像素边界；端点即游程的最左/最右像素边界 |
| **拐角像素化** | 拐角由两段 1px 笔画**共有**一个像素构成（4 邻接实心），不得"相邻但不相交" | 断笔（相邻不相交）在 12ppem 下表现为斜裂缝 |
| T 型交接 | 竖笔穿过横笔时，交点像素被两条笔画共有 | 交点像素必须有墨迹，缺一个即断 |
| **竖向游程合并** | 竖向相邻、x 范围相同的水平游程合并成**一个**矩形（像素并集不变） | `build_font.py::_merge_vertical_runs()`：轮廓数 **107,209 → 73,933**（−31%）；TTF **1,364,528 → 973,712 字节**（−28.6%）；整数倍精确性不变（**12,483 / 12,483**） |
| 合并的动机 | 非整数缩放下每个矩形**独立**吸附到输出网格 | 1.5px 的方块有的落进 1 格、有的整个落空 → 笔画断成虚线；合并后整条笔画共享一个矩形，吸附一致 |
| 合并方向 | 只做**竖向**合并（不横向） | 竖向合并已消除断笔主因；横向合并会跨越字形内部空洞，破坏墨迹并集 |
| 非等价前提 | 合并前后**像素并集必须完全相同** | 合并只改轮廓表达，不改位图；由 §3 AC-04 的回归比对保证 |

> 判定："笔画恒 1px"在本项目里不是美学偏好而是**可行性约束**：12px 格内做粗细对比，横向与纵向宽度只能各取一个值，等粗是唯一自洽解。

### 2.4 部件复用策略

#### 2.4.1 复用策略

| 策略 | 适用 | 收益 | 代价 |
|---|---|---|---|
| **逐像素等价复用**（bit-identical） | 在同一个 12 × 13 cell 内、像素完全相同的部件 | 复用最省力，且 100% 保住一致性；不需要额外规则 | 复用率受源字体自身部件一致性限制；本项目**尚无实测复用率**（见 §5 B-12） |
| **结构等价复用**（签名相同，像素可不同） | `sig_of()` 签名一致但栅格位置不同的部件（如不同部件宽度的同类骨架） | 可提高复用率，同时保持拓扑一致 | 需要人工挑选；复用件要重新落到目标字的具体位置 |
| **结构相似但像素不等 → 不复用** | 目视接近、实则像素有差的部件 | 避免"复用后某几个字看起来手绘" | 放弃部分本可复用的部件 |
| **不可跨 cell 复用** | 部件需要缩放或平移才能嵌入目标字的部件 | — | 12px 下缩放会引入非整数缩放，破坏 §2.3 的笔画恒 1px 规则；**直接否决** |
| **整字级源切换（等价性优先于视觉相似）** | 源字体之间存在"同码位不同画法"的问题 | 解决整格逐字节相同造成的符号歧义 | 需为每个例外指定来源 |
| **量化判据替代目视** | 判定两个部件是否可复用 | 把一致性问题变成可计算问题 | 只能回答结构量，不能回答位置是否正确 |

#### 2.4.2 量化工具

| 工具 | 度量 | 在部件复用中的用途 |
|---|---|---|
| `bitfont.py::count_runs()` | 位图的游程（笔画段）计数，与 `_merge_vertical_runs()` 使用的水平游程模型一致 | 判定两部件的笔画数是否同档 |
| `bitfont.py::count_holes()` | 封闭空洞数量 | 判定结构是否同档（`口`／`日`／`田` 类部件的封闭性差异） |
| `bitfont.py::ink_ratio()` | 墨迹像素占比 | 判定粗细／重心分布是否同档，防止复用出"一胖一瘦" |
| `bitfont.py::to_ascii()` | 位图 → ASCII 文本 | 逐像素 diff，评审时可直接贴出，不依赖看图 |
| `route_rule.py::sig_of()` | 结构签名 | 部件级结构比对的键；签名不等价只是"不可复用"，不是"构造错误" |

#### 2.4.3 整字级源切换的等价性判据（实例）

| 码位 | 现象 | 处理 | 机制 |
|---|---|---|---|
| `U+005C` 反斜杠 | MS Gothic 按 **JIS 惯例**把 `U+005C` 画成 `¥`，导致它与 `U+00A5` **整格逐字节相同**（两个码位画出同一张图） | 切到 fusion 源 | `bitfont.ScriptStack` 的 `overrides` 参数——源字体语系惯例问题的**专用通道** |
| 汉字路由 | 汉字不走 `overrides` | 由 `ideo_route.json` 单独路由，**3,010** 条路由记录 | `charset.load_ideo_route()` / `build_stack()` / `gate_ideo_route()` |

> 判定：复用与换源的**共同判据是"像素级等价"，不是"视觉上像"**。整格逐字节相同是比"画法不同"更严重的缺陷——它让 `\` 和 `¥` 无法区分。

### 2.5 笔画交接与连通性

| 项 | 值 | 说明 |
|---|---|---|
| 笔画宽度 | 恒为 1 像素 | 无例外（§2.3） |
| 端点 | 落在整像素网格线上 | 不允许半像素端点 |
| 拐角 | 拐角像素被两段笔画共有（4 邻接实心） | 相邻不相交 = 断笔 |
| 竖向游程合并对连通性的效果 | `中` U+4E2D @18ppem：连通域 **8 → 3** | 合并前竖向笔画被拆成多个独立矩形，在 1.5 倍缩放下各自吸附落空/落进，连通域膨胀到 8；合并后整笔共享一个矩形，连通域降到 3 |
| 非整数倍下的整体连通性 | 18ppem（1.5 倍非整数缩放）下仍有 **590 / 595** 字发生连通性变化 | **诚实边界**：构造规则不覆盖非整数倍缩放 |
| 非整数倍下的墨迹量 | 偏细 **43%** | 同上，18ppem |
| 整数倍精确性 | **12,483 / 12,483** 不变 | 合并前后在整数倍缩放下逐格一致 |
| 可承诺的字号 | 12ppem（9pt）、24ppem（18pt）、36ppem（27pt）@96dpi | 只有 12 的整数倍逐格还原设计 |
| GDI 逐格一致性 | 12ppem / 24ppem 下**全字符集 4,161 / 4,161 逐格一致**，抗锯齿像素 **0** | Windows / Word 的渲染路径 |
| FreeType 表现 | 12px 平均偏差 **19.00 px/字**（最坏 44）；24px+ 偏差 0 | Pillow / Chrome / Linux 路径；栅格化须走 FreeType **MONO 目标**（`FT_LOAD_TARGET_MONO`），默认灰度抗锯齿再二值化会得到"缩小的矢量字体"而非点阵 |

> 判定：**连通域数量是笔画交接的量化代理指标**。笔画断裂 = 连通域增加；笔画粘连 = 连通域减少。590/595 这个数字说明"合并竖向游程"解决的是**构造侧**的断裂（非整数缩放下的矩形独立吸附），但非整数缩放本身带来的断裂与墨迹变细属于**渲染侧**，两者不要混为一谈。

### 2.8 多语言扩展的字形结构要求

多语言版 `PixelFont Multi 12` 方案 C 的逐层账目（每层可加总复核）：L0 当前家族 4,161 → L1 +Latin Ext A/B 241（4,402）→ L2 +希腊 99（4,501）→ L3 +西里尔 151（4,652）→ L4 +韩文音节 11,172（15,824）→ L5 +JIS 假名/符号/全角 1,695（17,519）→ L6 +JIS 汉字 2,297（19,816）→ L7 +CJK 其余 11,576（**31,392**）。交叉核对：方案 A（L0–L6）= 19,816；CJK 整块 `U+4E00–U+9FFF ∩ Fusion ja` = 19,317；A ∪ CJK = **31,392** ✔。

| 要求 | 依据 | 状态 |
|---|---|---|
| 韩文音节 **11,172** 个 | L4：`U+AC00–U+D7AF ∩ Fusion ko` | 数量已定；**12px 下的结构可用性（笔画 ≤1px、墨迹框 ≤12×13、连通域与源一致）尚无实测 → 待验证**。验证方法：把 ko 源的 11,172 个音节逐个渲进 12 × 13 cell，按 §2.3 规则逐条检查 |
