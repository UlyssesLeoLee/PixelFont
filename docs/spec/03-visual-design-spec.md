# 03. 字体视觉设计规范

> 文档编号：PF-SPEC-03 ｜ 状态：规范（实现现状） ｜ 事实依据：统一事实底稿 v2（2026-10-24） ｜ 对应仓库 HEAD：`4300fc1`
> 适用家族：`PixelFont PC98 12`（PostScript 名 `PixelFontPC98-12`）；多语言版 `PixelFont Multi 12` 尚在规划中，见 §2.8。

## 结论先行

**本字体长什么样：** 一副 12×13 像素网格上的 PC-98 时代等宽点阵中文黑体 —— 每个字形都是 1 像素宽横竖笔画的正交并集，没有曲线、没有圆角、没有斜切、没有收笔锋芒，笔画宽度处处相等，整副字体在 12px 下被压到 12 个像素宽的全角格子里，在 24px / 36px 下等比放大后**逐格**复现同一副点阵。拉丁与假名来自 MS Gothic 的 JIS 谱系，汉字来自 GB2312 一级 3,755 字，其画风因此是"MS Gothic × SimHei 黑体"这一 PC-98 办公机上的典型日式中文点阵，而不是任何一款现代矢量黑体的缩微版。

**它的视觉规则由哪些可验证的约束决定：** 不是由"好看"决定，而是由四组硬约束共同锁死 —— ①**几何约束**：设计网格 12×13、UPM 768、1 像素 = 64 单位、基线 ascent 11 / descent 2、全角 advance 12 px（1 em）、半角 advance 6 px（0.5 em）、em 方框按字宽 12 而非 cell 高 13 取；②**造型约束**：笔画恒为 1 像素宽、横竖等粗、方笔无衬线、无曲线原语、圆角与斜接一律拒绝、笔画端点平齐；③**技术约束**：字形是矢量 TTF（有 `glyf` 表）但按点阵网格设计，每个像素先转成矩形轮廓，竖向游程再合并；④**渲染约束**：`gasp = {0xFFFF: 0}`，栅格化走 FreeType MONO 目标，输出 0/255 单色，**只有 12 的整数倍字号**能逐格还原设计。

**与"普通矢量字体的设计直觉"的三处根本冲突：**

| 直觉 | 本字体的规则 | 冲突的根源 |
|---|---|---|
| "字形可以按任意比例缩放" | 只有 12 的整数倍字号能逐格还原；18ppem（1.5 倍）笔画断裂且墨迹量偏细 **43%** | 点阵字体的设计意图是"像素即最小单位"，缩放必须落在像素网格上 |
| "轮廓应当贴合设计意图，渲染器负责抗锯齿" | 抗锯齿被**主动禁用**（`gasp` 禁 DOGRAY\|GRIDFIT），栅格化强制 MONO | 一旦引入灰度抗锯齿，点阵的硬边会退化成"缩小的矢量字体"，画风立刻变味 |
| "多边形越少越好，交给渲染器优化" | 每个像素一个矩形会让非整数倍缩放下每个矩形**独立吸附**到输出网格，1.5px 的方块有的落进 1 格、有的整个落空 → 笔画断成虚线；因此竖向游程**必须**合并：轮廓数 107,209 → **73,933**（−31%），TTF 1,364,528 → **973,712 字节**（−28.6%），整数倍精确性不变（**12,483 / 12,483**） | 优化目标不是"多边形数量"，而是"跨缩放比下的笔画连通性" |

结论：这份规范的可判定性来自**量化判据**（笔画游程段数、墨迹占比 `ink_ratio()`、封闭孔洞数 `count_holes()`、水平游程数 `count_runs()`、轮廓数、字节数、逐格一致率），而不是来自主观形容。凡本文写不出的数字，一律标「待验证」并给出验证方法。

## 1. 范围与目的

### 1.1 目的

定义 `PixelFont PC98 12` 的**视觉层**规格：字形长什么样（气质、笔画、粗细、曲线、重心）、每一条规则如何被判定、以及这些规则与"矢量字体设计直觉"冲突在哪里。本文的目的是让任何人（包括后续维护者、评审者、以及未来多语言版 `PixelFont Multi 12` 的实施者）能够**在不询问作者的前提下**，用可执行的方式判断某个字形或某个改动是否合规。

本文不重复描述字体的构建流程、字符集账目、OS/2 元数据修复与发布流程 —— 那些属于本套 12 份文档的其他分册；本文只引用它们的事实结论。

### 1.2 适用范围

| 项 | 内容 |
|---|---|
| 覆盖家族 | `PixelFont PC98 12`（4,161 码位）；规划中的 `PixelFont Multi 12`（31,392 码位）仅在 §2.8 与 §5 出现 |

| 事实基线 | 统一事实底稿 v2（2026-10-24 核实），对应仓库 HEAD `4300fc1` |

### 1.4 术语

| 术语 | 定义 |
|---|---|
| 设计网格 | 字形设计的最小单位网格，本字体为 **12 宽 × 13 高**像素；1 像素 = 64 单位（UPM 768 / 12） |
| cell | 12×13 的字形容纳格；基线在第 11 行下方，cell 共 13 行 |
| 字面框 | 字形被允许落墨的矩形区域；全角为 12×13 px，半角为 6×13 px |
| 墨迹（ink） | 实际落墨的像素集合；像素并集即字形的可见形状 |
| 游程（run） | 同一行内连续的一段墨迹像素；`count_runs()` 统计其数量 |
| 封闭孔洞（hole） | 被墨迹完全包围的空白连通区；`count_holes()` 统计其数量 |
| 墨迹占比 | `ink_ratio()` = 墨迹像素数 / 字面框像素数 |
| 4 邻域 | 上、下、左、右四个正交相邻像素；**不**含对角 |
| 8 邻域 | 4 邻域 + 四个对角相邻像素 |
| 整数倍精确 | 字号为 12 的整数倍（12 / 24 / 36 ppem）时，栅格化结果与设计位图逐格一致 |
| 逐格一致 | 两个位图在 12×13 格内逐像素相等，无抗锯齿中间灰度 |

## 2. 正文

### 2.1 字体气质与历史定位

| 维度 | 规格 | 依据 | 验证方式 |
|---|---|---|---|
| 时代定位 | PC-98 时代 12px 等宽点阵；生产源之一即 MS Gothic（JIS 谱系），直接承载 PC-98 画风 | 底稿 §4 生产源表；家族名 `PixelFont PC98 12` / `PixelFontPC98-12`（底稿 §1） | `python -c "from fontTools.ttLib import TTFont; f=TTFont('dist/PixelFontPC98-12.ttf'); print(f['name'].getDebugName(1), f['name'].getDebugName(6))"` 期望：`PixelFont PC98 12` / `PixelFontPC98-12` |
| 网格 | 设计网格 **12 × 13 像素**（宽 × 高），12px 等宽 | 底稿 §2 | `build_font.py` 的 `UPM` 常量与 `cell_w` / `cell_h` 定义；产物 `head.unitsPerEm` 应为 768 |
| 比例 | 全角 : 半角 = 12 : 6 = 2 : 1 | 底稿 §2 advance 段 | 读产物 `hmtx`：全角 advance = 768 单位，半角 = 384 单位 |
| 像素风 | 1-bit 单色，0 / 255 两级灰度，无中间灰 | 底稿 §8（MONO 目标，输出 0/255 单色 L 图） | `tools/fontgen/verify_gdi.py`；栅格化输出直方图应只有 0 与 255 两个值 |
| 终端感 | 12px 是第一可用字号；只有 12 的整数倍（12 / 24 / 36 ppem）能逐格还原 | 底稿 §8 | `docs/word-compat.md` §7.6；`verify_all.py` 第 8 步 |
| 汉字面 | GB2312 一级 **3,755** 字，**机械推导**（区位 16–55 区，`0xB0A1`–`0xD7F9`），非凭记忆列表 | 底稿 §3 | `tools/fontgen/charset.py::gb2312_level1()`；回归门禁第 3 步 |
| 假名面 | 假名 **255** 字（平假名 `U+3041`–`U+309F`、片假名 `U+30A0`–`U+30FF`、半角片假名 `U+FF61`–`U+FF9F`，外加 `々 〆 〇 ヶ ー ～`） | 底稿 §3 | `charset.py::kana_chars()`（258 项，去重后计 255） |
| 字重 | **单字重** Regular，无 Bold / Italic / 可变轴 | 底稿 §12 | `f['OS/2'].usWeightClass` == 500 且 `f['fvar']` 不存在 |
| 家族规模 | **4,161** 码位（ASCII 95 + 标点符号 56 + 假名 255 + 汉字 3,755，源列表合计 4,164，去重后 4,161） | 底稿 §3 | `charset.py::build_charset()` 返回长度 |
| 历史谱系的自证缺陷 | 字形派生自 SimHei / MS Gothic（微软专有）；引入 Ark Pixel 作生产源后 Ark 票变自证，目视复核参考列改为 **Zpix + Unifont** | 底稿 §5 / §12 | `docs/reference-fonts.md` |

### 2.2 笔画风格

| 笔画特征 | 规格 | 依据 | 验证方式 |
|---|---|---|---|
| **笔画恒为 1 像素宽** | 任意横笔画在列方向上的厚度恰为 1 px；任意竖笔画在行方向上的厚度恰为 1 px | 本规范第一造型约束；与 §2.3 weight 取值绑定 | 位图上做逐行布尔差分：对每个水平墨迹游程 r（行 y，列区间 `[x0,x1]`），要求该区间在 `y-1` 行与 `y+1` 行**均无墨迹**；成立即厚度 = 1 px |
| **方笔无衬线** | 笔画起止为平齐方头，无衬线、无喇叭口、无三角形出锋 | PC-98 点阵共性；生产源 SimHei（黑体）/ MS Gothic（ゴシック）均为无衬线 | 视觉目视 + §3 A-02 的对角邻接判据（人眼复核由 Zpix / Unifont 兜底） |
| **横竖等粗** | 横画厚度 = 竖画厚度 = 1 px；不存在局部加粗或收细 | 本规范第二造型约束 | 对每个竖直墨迹游程做同样的上下/左右差分，结果须与横向一致 |
| **无曲线无圆角** | 字形中不存在任何曲线原语；轮廓全部由轴对齐矩形构成；不允许以像素阶梯伪造圆弧 | 每个像素 → 一个矩形轮廓（TrueType 坐标，y 向上）；`glyf` 中无二次曲线 | 检查轮廓点集：所有 on-curve 点须位于 64 单位整数倍坐标上（像素格角点），且无 off-curve 控制点 |
| **无斜接、无斜切** | 撇捺等斜笔以 1 px 台阶近似，不使用斜切角 | 12×13 网格内斜切角会落在非格点坐标 | 轮廓点集坐标检查（同上） |
| **端点平齐** | 笔画末端为水平或垂直的方头，不做收笔处理 | PC-98 点阵共性 | 目视 + §3 A-01 游程厚度判据 |
| **像素格对齐** | 所有轮廓矩形的边坐标为 64 单位的整数倍（即格点） | 1 像素 = 64 单位（UPM 768 / cell_w 12） | `build_font.py::_emit_rect()`；产物 `glyf` 坐标全为 64 的倍数 |
| **零抗锯齿请求** | `gasp = {0xFFFF: 0}`，不请求灰度抗锯齿（DOGRAY）也不请求网格拟合（GRIDFIT） | 底稿 §6；`verify_ttf_metadata()` 硬拦 | `verify_ttf_metadata()` 断言；`print(f['gasp'].gaspRange)` 期望 `{65535: 0}` |

### 2.3 笔画粗细控制

| `BitmapFont.weight` 取值 | 效果 | 适用 | 依据 / 验证方式 |
|---|---|---|---|
| 0（基线） | 不膨胀；笔画恒为 1 像素宽 | **本家族全部 4,161 码位**（当前唯一实际取值） | 12ppem 下 GDI 逐格一致 4,161/4,161、抗锯齿像素 0（底稿 §8）；回归门禁第 3 步"产物与源位图逐像素一致" |
| 1 | 4 邻域膨胀 1 圈；横竖笔画变为 2 px 宽 | 预览图 / 低分辨率下加粗的替代手段（**本家族未启用**） | 参数名与默认值的精确形式**待验证** —— 验证方法：`grep -n "weight" tools/fontgen/bitfont.py`，再 `python -c "from tools.fontgen.bitfont import BitmapFont; ..."` 读取实际 `weight` 属性 |
| ≥ 2 | 4 邻域膨胀 2 圈及以上；12×13 网格内笔画迅速占满，字形发糊 | 仅 16px 以上网格的实验用途（**本家族未使用**） | 同上；本家族为单字重 Regular（底稿 §12） |

**膨胀邻域的选择（本规范明确禁用 8 邻域）：**

| 邻域 | 对斜边的效果 | 判定 |
|---|---|---|
| **4 邻域**（上 / 下 / 左 / 右） | 斜边保持 1 px 台阶，与点阵字体"逐格画"的心智一致 | **采用** |
| 8 邻域（含对角） | 对角相邻的像素被填实，1 px 的斜向笔画被**糊成 2 px 宽的实块**，阶梯感消失 | **不采用** |

- 理由（可判定）：在 4 邻域膨胀下，一条 45° 的斜笔其像素集合为逐格阶梯；改用 8 邻域后相邻阶梯像素互为对角邻居而被判为"相邻"，斜笔在字面上呈现为连续的实心色带 —— 视觉上从"手绘点阵"退化为"缩小的矢量字体"，与 §2.1 的终端感直接冲突。
- 该规则目前**没有对应的自动门禁**；落地方式待办（见 §5 B-07）。
- 邻域选择的源码落点**待验证**：验证方法 `grep -n "weight\|dilate\|neighbour\|neighbor\|4\b" tools/fontgen/bitfont.py`，定位膨胀实现并确认使用的是 4 邻域偏移集合。

### 2.4 曲线与转角处理

| 事项 | 规则 | 依据 | 验证方式 |
|---|---|---|---|
| 曲线的取舍原则 | 点阵字体里"曲线"只能以 1 px 台阶近似；**凡无法在 12×13 网格内以阶梯表达、且阶梯会挤占笔画本体的曲率，一律以直角折线替代** | 12×13 = 156 px 的信息量上限；曲线的阶梯化会把 1 px 笔画的净空挤成 0 | 对含曲笔的字（如 `扇`、`遍`、`雇` 等）目视复核 + 与 Zpix 对照（`verify_all.py` 第 4 步硬检查参考集含 Zpix） |
| 不引入圆角 | **明确拒绝**圆角与圆头。圆角在 1 px 笔画上需要 ≥ 2 px 的角部，会把 1 px 笔画局部扩成 2 px，破坏"横竖等粗" | 与 §2.2 一致；PC-98 12px 点阵无圆角先例 | §3 A-02：对角邻接判据 |
| 转角（折）像素化 | 折点落在格点上，转角以直角（横→竖 / 竖→横）表达；折的两臂各自保持 1 px 宽 | 轮廓全部为轴对齐矩形（§2.2） | `glyf` 轮廓点坐标检查 |
| 折角的两臂 | 竖向相邻、x 范围相同的水平游程**合并为一个矩形**（像素并集不变） | 底稿 §7（v1.0.0 起） | 见 §2.7 |
| 端点 | 端点为方头，行/列方向一次性收尾，不做渐变收细 | §2.2 | §3 A-01 |
| 曲线判定 | 字形内不存在任何非轴对齐的轮廓边 | 轮廓生成规则（每像素 → 一个矩形） | 产物 `glyf` 中所有轮廓点满足 `x % 64 == 0 and y % 64 == 0` |

> 取整（栅格化）规则的**具体阈值待验证** —— 底稿未给出"覆盖率 ≥ 多少落墨"这一参数。验证方法：`grep -n "threshold\|coverage\|>= 0\.\|round" tools/fontgen/bitfont.py`，定位采样到网格的判定式后补入本文 §5 B-08。

### 2.5 字面框与重心

| 项 | 值 | 说明 |
|---|---|---|
| 设计网格 | **12 × 13 像素** | 全角字面的宽 × 高 |
| UPM | **768** | 1 em = 768 单位 |
| 1 像素 | **64 单位** | 768 / 12 |
| em 方框 | 按**字宽 12** 取，**不是** cell 高 13 | 早先按 13 除会让 12ppem 下每像素落在 0.923 个设备像素上，整副字糊掉（底稿 §2） |
| 基线 | **ascent 11 / descent 2** | 基线在第 11 行下方；cell 高 **13** |
| 全角 advance | **12 px** = 768 单位 = 1 em | 全角字符（汉字、假名、全角符号） |
| 半角 advance | **6 px** = 384 单位 = 0.5 em | 半角字符（ASCII、部分符号） |
| 全角字面框 | 12 × 13 px = 156 px | `ink_ratio()` 的分母基准 |
| 半角字面框 | 6 × 13 px = 78 px | 半角字形只落在 advance 宽度内 |
| 半角落位 | **待验证** | 半角字形在 12 px 宽网格内的水平落位（居中 / 左对齐）待验证 —— 验证方法：在 `dist/PixelFontPC98-12-atlas.png` 上量取半角字形的实际列范围，或读取 `build_font.py` 中半角偏移量定义 |
| 竖向重心 | 基线上 11 px、基线下 2 px | CJK 字面在基线上下按 11 : 2 分配，避免下伸部与下一行粘连 |
| 量化工具 | `bitfont.py` 的 `count_runs()` / `count_holes()` / `ink_ratio()` | 分别为：水平墨迹游程段数（笔画分段数量）、被墨迹完全包围的空白连通区数、墨迹像素数 / 字面框像素数 |
| 量化工具签名 | **待验证** | 三者是 `BitmapFont` 的方法还是模块级函数待验证 —— 验证方法：`grep -n "def count_runs\|def count_holes\|def ink_ratio" tools/fontgen/bitfont.py` |
| 墨迹重心阈值 | **待验证** | 当前**没有**墨迹加权重心的量化门禁。验证方法：对 4,161 字计算墨迹像素加权重心 y 坐标分布，取 P5–P95 区间作为可接受阈值后写入门禁（§5 B-08） |
| 字面框与墨迹重心 | 字面框是**约束**（落墨不得越界），墨迹重心是**结果**（由笔画排布决定） | 二者不得混为一谈：前者由生成规则保证，后者由 `ink_ratio()` / 重心统计观测 |

### 2.6 视觉设计原则清单

每条原则都必须可判定。"要美观""要协调"这类句子一律不写。

| 编号 | 原则 | 可判定判据 | 验证方式 |
|---|---|---|---|
| P-01 | 笔画恒为 1 像素宽 | 任意水平游程的上下相邻行在其列区间内均无墨迹；任意竖直游程的左右相邻列在其行区间内均无墨迹 | 位图布尔差分（§2.2） |
| P-02 | 横竖等粗 | 横向游程厚度集合与纵向游程厚度集合均为 `{1}` | 同上 |
| P-03 | 方笔无衬线、无曲线、无圆角 | 轮廓点全为格点（坐标为 64 的倍数），无 off-curve 控制点；不存在"仅 2 个对角墨迹"的 2×2 子块 | `glyf` 坐标检查 + 2×2 子块扫描 |
| P-04 | 端点平齐 | 笔画末端为水平或垂直方头 | 轮廓点集 + 目视复核（Zpix 兜底） |
| P-05 | 像素格对齐 | 所有轮廓矩形边坐标 ≡ 0 (mod 64) | `_emit_rect()` 断言 |
| P-06 | 零抗锯齿请求 | `gasp = {0xFFFF: 0}`，且 `gaspRange` 不含 DOGAY(0x02)/GRIDFIT(0x01) | `verify_ttf_metadata()` |
| P-07 | 单色输出 | 栅格化直方图只含 0 与 255 | `verify_gdi.py` / MONO 栅格化 |
| P-08 | 等宽、全半角 2:1 | 全角 advance = 768，半角 advance = 384 | 产物 `hmtx` |
| P-09 | 基线与重心 | ascent 11 / descent 2；基线上下按 11 : 2 分配 | `build_font.py` 常量 + `BitmapFont.cell_ascent` / `cell_descent` |
| P-10 | 笔画连通性优先于轮廓数 | 竖向游程必须合并：合并前后像素并集**逐像素相等**，且整数倍精确性不下降 | §2.7 数字 + 回归门禁 |
| P-11 | 膨胀只用 4 邻域 | 膨胀后的像素集合中不出现"仅对角相邻"的墨迹对 | 膨胀实现处断言 + 2×2 子块扫描 |
| P-12 | 12 的整数倍精确 | 12 / 24 / 36 ppem 下 **12,483 / 12,483** 次比对全部逐格一致 | `verify_all.py` 第 8 步 + `verify_gdi.py` |
| P-13 | 字形不得越出字面框 | 墨迹完全落在 12×13（全角）/ 6×13（半角）cell 内 | 逐字位图边界检查 |
| P-14 | 形态指标可观测 | 每个字形都可给出 `count_runs()` / `count_holes()` / `ink_ratio()` 三项数值 | `bitfont.py` 三个函数 |

### 2.7 点阵风与矢量化路线的取舍

**前提：本字体是矢量 TTF（有 `glyf` 表），但按点阵网格设计。** 二者不矛盾 —— 交付物是轮廓字体，但每一个轮廓矩形的边都严格落在像素格点上；"矢量"只是交付格式，"点阵"是设计语言。

| 项 | 规格 / 数值 | 依据 | 验证方式 |
|---|---|---|---|
| 轮廓生成规则 | 每个像素 → 一个矩形轮廓（TrueType 坐标系，y 向上）；所有矩形同向绕向，用 non-zero 环绕规则填充 | 底稿 §7 | `build_font.py::_emit_rect()` |
| 逐像素独立矩形的**问题** | 非整数缩放下每个矩形**独立**吸附到输出网格：1.5px 的方块有的落进 1 格、有的整个落空 → 笔画断成虚线 | 底稿 §7 动机段 | 18ppem 渲染对比（`docs/word-compat.md` §7.6） |
| 游程合并规则 | **v1.0.0 起**：竖向相邻、x 范围相同的水平游程合并成一个矩形（像素并集不变） | 底稿 §7 | `build_font.py::_merge_vertical_runs()` |
| 轮廓数 | 107,209 → **73,933**（**−31%**） | 底稿 §7 | 构建日志；`glyf` 轮廓计数 |
| 文件体积 | TTF 1,364,528 → **973,712 字节**（**−28.6%**） | 底稿 §7 / §10 | `dist/PixelFontPC98-12.ttf` 字节数 = 973,712，sha256 `3298AE4D9E28E7F3D5939E007DF43EA82B64860922AB246FC7A4B82414F69FB1` |
| 整数倍精确性 | **不变**，**12,483 / 12,483**（= 4,161 码位 × 3 个整数倍字号 12 / 24 / 36 ppem） | 底稿 §7 | `verify_all.py` 第 8 步 |
| 非整数倍表现 | 18ppem（1.5 倍）：笔画断裂 + 墨迹量偏细 **43%** | 底稿 §8 | `docs/word-compat.md` §7.6；`reports/gdi_compat.json` |
| 栅格化目标 | **FreeType MONO**（`FT_LOAD_TARGET_MONO`，等同 GDI 1-bit 文字），输出 0/255 单色 L 图 | 底稿 §8 | 栅格化代码路径 |
| 禁用方案 | Pillow 默认灰度抗锯齿再二值化 —— 会得到"缩小的矢量字体"而不是点阵 | 底稿 §8 | 同上 |
| GDI 表现 | 12ppem 与 24ppem 下**全字符集 4,161 / 4,161 逐格一致**，抗锯齿像素 **0**（本机字体平滑开启时也是 0） | 底稿 §8 | `tools/fontgen/verify_gdi.py`；`reports/gdi_compat.json` + `reports/gdi_raster_scan.tsv`（逐码位 4,162 行） |
| FreeType 表现 | 12px 平均偏差 **19.00 px/字**（最坏 44），24px 及以上偏差 0 | 底稿 §8 | `docs/word-compat.md` §7.5 |
| 内嵌位图（EBDT/EBLC） | GDI **会**采用，但**只在请求字号与 strike 的 ppem 精确相等时**；不会拿最近的 strike 缩放 | 底稿 §8 | `docs/word-compat.md` §7.7 |

**取舍结论：** 本字体选"**矢量交付 + 点阵设计 + MONO 栅格化 + 竖向游程合并**"这一组合，而不是"纯点阵格式（BDF-only）"路线。理由是纯 BDF 无法在 Word / 浏览器等以 `glyf` 栅格化的路径上逐格还原；而合并竖向游程恰恰把矢量交付的最大风险（非整数倍缩放下的断裂）压到只剩"非整数倍不精确"这一个已知且已量化的代价（墨迹偏细 43%）。

### 2.8 多语言扩展的视觉要求

多语言版 `PixelFont Multi 12`（**独立家族**，不改现有 `PixelFont PC98 12`；范围 = 方案 C = **31,392 码位**）尚在规划中。本节给出它必须满足的**视觉层**要求；账目与覆盖率细节见 §5 B-06 与底稿 §13。

| 要求 | 依据 |
|---|---|
| **多语言版以 Fusion Pixel 12px 各变体为源**（ja / ko / latin / zh_hans / zh_hant / zh_kw 七变体，OFL-1.1） | 底稿 §5、§13；上游 `vendor/fusion-pixel-12px/` |
| 画风差异的处理：Fusion Pixel 12px 与本家族 PC-98 风格的差异（12px 点阵、1 px 笔画、单色 —— 但具体字面比例、灰度取向、汉字部件写法与本家族不完全一致）**不得靠后期描边或加滤镜修正**，只能靠**逐字取舍**：与本家族风格一致的直接采用，冲突字形回到 §4 生产源（SimHei / MS Gothic）路径 | 底稿 §4 生产源表 + §13 逐层账目；本规范 P-01 ~ P-04 的可判定约束要求字形在合并后仍满足 1 px 笔画与横竖等粗 |
| 中日共享 2,078 汉字中 **434 字**的 ja / zh 字形分歧：**中日字形分歧真实存在**（2,078 中像素完全相同 1,644 = **79.1%**，不同 **434 = 20.9%**） | 底稿 §13.3（逐像素实测，12×13 单色 cell） |
| "**中文形为主**"策略：共享字默认取 zh_hans 形（中文形），JIS 独有 2,297 字走 ja 源；GSUB `locl` 变体机制**未选**（架构改动过大） | 底稿 §13 决策 ③ |
| 对视觉一致性的影响：共享字统一为中文形 → 日文语境下约 **20.9%** 的共享汉字呈现非惯用字形（如 `直` U+76F4 异或 28 格、`氏` U+6C0F 异或 26 格、`才` U+624D 异或 25 格），这是**已知且被接受的**视觉不一致，而非缺陷 | 底稿 §13.3 差异最大字清单（`肩` 78 / `扇` 71 / `房` 69 / `雇` 69 / `遍` 59 / `扁` 54 / `煽` 53 / `灰` 44 / `曾` 41 / `罪` 40 / `偏` 38 / `奠` 38 / `判` 37 / `歉` 35 / `遥` 30 / `滞` 29 / `直` 28 / `氏` 26 / `才` 25） |
| 异或格数分布（用于评估"统一为中文形"的视觉代价）：1 格 102 字、2 格 94 字、3 格 40 字、4 格 42 字、5 格 27 字、6 格 18 字，**≥7 格共 93 字**，最大 78 格 | 底稿 §13.3 |
| 覆盖缺口：`U+20AC €`、`U+2260 ≠`、`U+2264 ≤`、`U+2265 ≥` 四个码位**不被任何 Fusion 变体覆盖**，须沿用非第三源路径（MS Gothic / SimHei） | 底稿 §13.4 |
| 体积代价：当前 4,161 字 = 973,712 字节 → 平均 **234.0 字节/字**；方案 C 31,392 字粗估约 **7.0 MB**（实际会因 CJK 字形复杂度不同而偏离） | 底稿 §13.5 |
| 非 CJK 语系（Arabic / Hebrew / Devanagari / Thai）**不纳入**方案 C：只有 Unifont 16（16×16 网格），塞不进 12px 格 | 底稿 §13.6、§12 |
