### B 项的判定依据

`U+53E0 叠` 的骨架部件是「冖 + 又 + 又 + 又 + 且」。12px 下「且」必然是压缩画法,
但**框内的两道横隔不能消失**。逐位图核对:

```
我方 (12x13)          Zpix (12x13)
.#######........      .#########......
..###.#.#.......      ...#...#........
.#######........      ....###.........
##########......      #####.#####.....
..##...##.......      .#..#.#..#......
##...##.##......      ..##...##.......
#####.##.#......      ###############.
#.######........      #.#.....#.#.....
..######........      ..#######.......
..######........      ..#.....#.......
##########......      ###############.
```

我方第 7–9 行的右半边是 **6×3 的实心带**（`#.######` / `..######` / `..######`）,
而 Zpix 在同一位置是 `#.#.....#.#` / `..#######` / `..#.....#` —— 「且」框内的两道横隔清晰存在。
Unifont 16px 同样把「且」的框画得完整。**「且」的封闭空间被填实 = 骨架信息丢失**,
且两个参考一致可辨, 故判 B（置信度 high）。

## 6. 复核方法

1) 按协议第 3 节几何 (格 108x66 / 表头 26 / 三列 x = +2,+38,+74 / 纵 y+30 / 槽位 16x16 放大 2 倍) 从 6 张 PNG 原图逐格抽取 我方 / Zpix / Unifont 三列位图; 把抽出的位图放大贴回原图逐像素复原比对 —— 576 格 x 3 列 = 1728 个区域全部一致 (0 处不符), 同时确认三列无「缺」字格、无跨格串位 (槽位 16x16 已生效, 无 Unifont 溢出污染)。

2) 字腔量具自检: 写三份互不同构的实现 (边界洪泛 BFS / 并查集标号 / 最小标签传播), 在全部 1728 个字形上互校 —— 首轮「逐行行程」实现有 bug (跨行合并时未更新上一行标签), 20/1728 不一致, 换实现后 0/1728 不一致, 量具才被采用。

3) 量化筛查: 字腔数 / 墨量 / 4-邻接连通块 / 墨量比 (我方 vs Zpix, 同为 12px)。576 字中无空白字形、无两个码位位图完全相同; 墨量比最高仅 1.23 (U+63A3 掣), 无成片加粗; 字腔数我方 < Zpix 且 < Unifont 的共 29 格, 逐格列入存疑候选。

4) 身份 (A 类) 判定以目视为主: 576 格按 4 列 x 3 行分块放大 3 倍逐格通读 (54 张裁切图, 每张 12 格), 逐格把「我方点阵」与「格内微软雅黑标注字 + 码位」及两个参考对照; 候选格再 6 倍放大复看。576 格无一格画错字。

5) 辅助筛查 (像素级, 已知分辨力有限, 只作参考不作依据): 像素 Dice 置换检验最佳匹配未指向自身 570/576 (中位余量 0.044, 对本批汉字无分辨力); 多尺度密度剖面置换检验对 Zpix 自身即最佳命中率 0.481 (随机置换基线 0.002, 约 240 倍提升), 对 Unifont 0.007 (基线 0.002, 近乎无分辨力)。故身份结论只以目视为准。

6) B/C 判定按骨架不按像素: 只有「某个封闭部件的空间被填实 / 部件并成实心带 / 部件分隔不可辨」才判 B; 笔画比参考密但结构仍可追踪判 C; 两个参考之间本身不一致的不硬判。像素级差异 (Zpix 画风更粗犷) 一律不算劣化。

### 量具自检（协议第 5 节 / 第 7 节第 6 条）

字腔量具写了**三份互不同构的实现**, 在全部 1728 个字形（576 格 × 3 列）上互校:

| 实现 | 方法 | 结果 |
|---|---|---|
| A | 边界洪泛 (BFS 从 bbox 边界白像素出发) + 剩余白区 BFS 计数 | 基准 |
| B | 并查集 (union-find) 白区标号 + 按是否触边剔除 | 1728/1728 与 A 一致 |
| C-初版 | 逐行行程 (run-length) 连通标号 | **20/1728 不一致 —— 实现有 bug, 弃用** |
| C-改版 | 最小标签传播 (cellular-automaton 式迭代) | 1728/1728 与 A、B 一致 |

C-初版的 bug 是**跨行合并行程标签时没有回写上一行的标签**, 导致一个连通块被拆成两个,
腔数多算 1。**这个 bug 的表现和实现正确时一模一样**（腔数仍是合理的整数, 不报错）,
只有交叉验证才抓得到 —— 正是协议第 5 节警告的情形。量具只有在 1728/1728 三方一致之后才被用于判定。

### 抽取工具自检

按协议第 3 节几何抽出的三列位图, **放大贴回原 PNG 逐像素复原比对**:
576 格 × 3 列 = 1728 个区域, **0 处不符**。这同时证明了三件事:

1. 抽取的几何与出图工具一致（没有读歪格位）;
2. 槽位 16×16 已生效, **Unifont 墨迹没有溢出串格**, 三列互不污染;
3. 三列**没有「缺」字格** —— 576 字在 Zpix 与 Unifont 中全部有字形, 不存在参考缺失导致的空栏。

### 辅助量化筛查（像素级, 只作参考不作依据）

| 检验 | 结果 | 分辨力评估 |
|---|---|---|
| 我方 576 字中是否有空白字形 | 0 | — |
| 我方 576 字中有无两个码位位图完全相同 | 0 | 排除「两个码位画成同一个字」 |
| 墨量比（我方 / Zpix, 同为 12px）最高值 | 1.23（`U+63A3 掣`） | 无成片加粗 |
| 像素 Dice 置换检验 | 最佳匹配未指向自身 570/576, 中位余量 0.044 | **对本批汉字无分辨力**, 不作依据 |
| 多尺度密度剖面置换检验 vs Zpix | 自身即最佳命中率 0.481（随机置换基线 0.002, 约 240 倍提升） | 有分辨力但不足以逐格定案 |
| 多尺度密度剖面置换检验 vs Unifont | 自身即最佳命中率 0.007（基线 0.002） | **近乎无分辨力** |

**关键说明**: 旧一轮的「置换检验每个字最佳匹配都指向自身」是在 **Fusion** 参考下得到的。
Fusion zh_hans 与 Ark zh_hans 结构距离 0.00, 而 Ark 是本项目的生产源 —— 那种「自匹配」
在很大程度上是**自己和自己比**的结果。换到独立的 Zpix + Unifont 后, 像素级置换检验
**不再指向自身**（Zpix 命中率 0.481, Unifont 0.007）。这**不能**读成「我方画错了」——
两个参考与生产源本就是不同画风 —— 但它说明**像素级置换检验不能用来给身份结论背书**,
本 lane 的 A 类结论因此完全建立在 576 格逐格目视之上。

## 7. 边界与说明

- **判定按骨架, 不按像素**。Zpix 画风比 Ark/Fusion 粗犷, 与我方的像素级差异一律不算劣化;
  只有「封闭空间被填实 / 部件并成实心带 / 部件分隔不可辨」才判 B。
- 我方字体是 12×13 网格, Unifont 是 16×16 —— 纵向不可直接比像素, 本报告只比骨架。
- 本轮 6 张图**没有出现「缺」字格**（576 字在两个参考中全部有字形）, 无需跳过任何格。
- 未出现旧图那种 Unifont 墨迹串到「我方」列左缘的污染（复原比对 0 处不符即佐证）。
- 本报告只回答「我方那一列画的是不是标注的那个字、结构有没有塌」;
  字形美观度、字重、字距不在本 lane 范围内。
- 复核期间 `tools/fontgen/` 可能被集成者并发修改 —— 本报告的结论一律以 PNG 原图为准, 不受源码变动影响。
