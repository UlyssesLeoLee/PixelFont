## 3. 方法说明

### 3.1 几何自校 (不靠协议, 从像素实测)

从 `glyphcmp_039.png` 实测确认: 格左上角 = `(c*108, 26+r*66)`; 标签字形 (白色墨迹) 在格内 `rel x5..22 / y9..26`, 旁边的码位文本是暗灰 (值 52), 不参与识别; 三列点阵槽位分别位于 `rel x+2 / x+38 / x+74`, 纵坐标均为 `y+30`, 每个槽 32×32 屏幕像素 = 16×16 源像素 (2 倍放大)。

### 3.2 格位映射独立复核 ✔

按协议要求, **没有**靠图上的低分辨率标签条带读码位。做法是把 index 里这一批字用**微软雅黑** (14~25 号共 12 档) 渲染成模板, 与 PNG 每格自带的白色标签做互相关:

- 打分器 A: 灰度归一化相关 (NCC), 把渲染字缩放到与标签裁片同尺寸后比对;
- 打分器 B: 二值 IoU, 双方 64×64 超采样后阈值化。

两个打分器**各自独立**取 argmax, 与 index 的码位比对:

| 打分器 | 与 index 不符的格数 |
|---|---|
| A (灰度 NCC) | **0 / 396** |
| B (二值 IoU) | **0 / 396** |

中位得分 (IoU) 0.991。另外: 396 个我方位图**互不相同**、**无空槽**, 可排除复制粘贴式的身份错误。

> 首版打分器 (统一缩放到 32×32 + 阈值) 曾在 `glyphcmp_040.png` 第 56 格报出一次不符, 经放大目视确认是**打分器**在细笔画上的假阳性 (该格码位 U+7AE0 = 章, 标签确实就是章), 换用上面两版打分器后归零。**这一格的人工复核结论保留在 `rejected_candidates` 里。**

### 3.3 逐格目视

每格裁成 `[标签 | 我方 | Zpix | Unifont]` 四联图, 放大到 8 倍逐格过; 对任何可疑格再出 16 倍放大图, 并打印 16×16 源位图的逐行 ASCII 与两个参考逐行对照。**身份判定只靠目视** (标签 + 两个参考同时在场)。

### 3.4 量化只作分诊, 且量具必须自检

| 量具 | 自检结果 | 用途 |
|---|---|---|
| 字腔数 (协议第 5 节) | 洪水填充 vs 并查集两份独立实现, 全部 **1188/1188 一致**; 合成对照 (环=1 腔, C 形=0 腔) 正确, 而**故意写错**的「把贴边白区也算腔」版本在 C 形上给出 1 —— 正是协议点名的那个坑; 对照试验: 两参考一致给腔数的 240 格中我方一致 **82.9%** (既非 100% 也非随机) | 采用 (分诊 + 判据证据) |
| 堆叠腔指标 v3 | 合成对照 (0~4 道内部横画 → 堆叠 1~5) 全对; 并查集连通分量 vs 迭代标号传播两份实现, **1188 次测量 0 次不一致**; 两参考一致的 225 格中我方一致 **84.0%** | 仅作分诊线索 (把 396 缩到 13), 逐条放大目视后才落判 |
| 我方位图 vs 标签字库形状匹配 (身份筛查) | **否决** | 真码位只排第 1 的比例仅 **1.5%** (6/396), 最佳匹配几乎总是「雨/再/予/宇」这类笔画少的常用字 —— 它测的是笔画密度不是身份, 无分辨力 |
| 水平小腔计数 (宽≥3 且 高≤3) | **否决** | 强烈依赖书写风格 (把明显无盒部件的「禹」「租」「阻」「重」「最」也报出来), 无分辨力 |
| 堆叠腔指标 v1 / v2 | **作废** | v1 相邻性判据写错 + 两实现互不一致; v2 的合成对照构造本身就错了 (内部横画画在错误的行), 两实现的分组语义也不同 (1188 次里 73 次不一致) |

> 被否决的指标**没有用于任何判定**, 仅在此如实记录。
