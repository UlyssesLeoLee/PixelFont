## 方法说明

- **artifact**: reports/glyphcmp_png/glyphcmp_000.png ~ glyphcmp_005.png (6 张, 576 格)
- **refs**:
  - Zpix 12px (MIT)
  - GNU Unifont 16x16 (GPL-2.0+)
- **basis**: 全部判定以出图 PNG 原图为唯一底本; 格位映射取自 reports/glyphcmp_index.json 的 sheets[].chars
- **steps**:
  - 协议核对: 读 docs/glyph-review-protocol.md, 判定口径按 A(画的不是这个字)/B(是此字但结构丢失)/C(边界情况) 三类; 参考列经 index refs 确认为 zpix + unifont-16 (index slot_w/slot_h=16)
  - 出图版本钉死: 本轮复核所用 6 张 PNG 与 reports/_tmp_lane1/snapshot_191142/ 下的快照逐张 SHA256 比对一致 (6/6 same=True), 判定不随集成者并发重出图而漂移
  - 位图还原: 用 reports/_tmp_lane1/extract.py 把 PNG 像素按 (源像素 i,j) = (屏幕 ox+2i, base_y+2j) 反解回 16x16 槽位内的 0/1 位图, 三列共 1728 个字形全部抽出; QC: 2x2 块不一致 0 处, 我方位图缺失 0 处
  - 量具自检: 字腔数用两份**不同实现** (BFS 边界洪水填充 + 并查集) 对 1728 个字形各跑一遍, 分歧 0 处, 数字可用 (协议第 5 节要求)
  - 目视复核: 48 张对照拼图 (每张 12 格, 我方|Zpix|Unifont, 4x/5x 放大) 逐张过完 576 格, 每格都对照左上角标注字与码位判断; 存疑格再用 10x~16x 单格重裁 + ASCII 点阵逐像素核对
  - 判定原则: 按骨架不按像素; 只有部件封闭空间被填实 / 横画消失致部件变样 / 并成实心带 才判 B; 轮廓可辨但笔画更粗或更细判 C; 仅位置(在字身框内的左右半区)偏离参考、字形骨架完好者判 C 并注明是位置差异
  - 旁证: 6 张表的格位映射直接取自 index JSON 的 sheets[].chars (权威), 未靠图上低分辨率标签读码位
- **quant_tool**:
  - `name`: reports/_tmp_lane1/measure.py (impl1 BFS 洪水填充 + impl2 并查集)
  - `selfcheck`: 1728 glyphs (576 格 x 3 列), 0 disagreements
  - `aux_scripts`: ['reports/_tmp_lane1/extract.py', 'reports/_tmp_lane1/measure.py', 'reports/_tmp_lane1/zoom.py', 'reports/_tmp_lane1/show.py (ASCII 点阵逐像素核对)', 'reports/_tmp_lane1/triage.py (三列外接框+字腔 紧凑摘要)']
- **notes**:
  - 本 lane 未修改 tools/fontgen/ 或任何源码; 复核期间源码可能被集成者并发改动, 不影响本结论
  - 已确认 gen_glyphcmp_sheets.py 把我方字形按槽位左上角原样贴图 (不做居中), 故我方墨迹的位置差异是字库自身的差异, 不是出图工具造成的
