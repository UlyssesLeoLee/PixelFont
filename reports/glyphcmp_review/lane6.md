## 5. 方法说明

1. 协议核对: 读 docs/glyph-review-protocol.md, 判定口径按 A/B/C 三类; 参考列确认为 Zpix + Unifont (index refs=['zpix','unifont-16']), 槽位 16x16 (index slot_w/slot_h=16), 无旧图溢出污染
2. 出图几何复核: 读 tools/fontgen/gen_glyphcmp_sheets.py, 确认 cell_w=108/cell_h=66/header=26/base_y=cy+30/ox=cx+2/38/74 与协议第 3 节一致, 并确认 entries=(ord(ch), ch, cat, ch) 使 index 的 chars、格内标注字形与三列点阵按构造绑定同一码位
3. 格位映射自检: 用 msyh.ttc@20px 在 (cx+4, cy+3) 重绘格内标准答案字形, 与 PNG 逐像素比对, 480/480 逐像素完全相同 (0 处差异)
4. 量具自检: 字腔数用两份独立实现 (BFS 洪水填充 + 并查集), 对 480 格 x 3 列共 1440 个字形跑一遍, 分歧 0 处, 数字可用
5. 极性校正: 三列都是**黑底白字**, 墨=白 (v>=128); 槽位 16 行里我方字形只占 8-12 行, 其余是空槽位而非墨迹。1440 个槽位的 2x2 放大块全部均匀 (非均匀块 0 个), 无抗锯齿
6. 身份旁证 (3 项): 无空我方位图 (0); 无两个码位共用同一我方位图 (0); 无我方位图与**别的**码位的参考位图逐像素相同 (0); 另有 9 个我方位图与同码位 Zpix 逐像素相同 (皆为简单字, 正常)
7. 身份判据的标定: 先试「膨胀 IoU」, 发现其无分辨力 (错配字对 p99=0.941 vs 正确配对 p50=0.922), 遂弃用; 改用双向 Chamfer 距离做**最近邻分类**: 把每一格的我方位图与本批 480 个 Zpix 位图逐一比, 本码位的 Zpix 在 480/480 格都排进前二 (220 格排第一, 其余被形近字抢到第一但差距 <=0.27 px)
8. 目视复核: 20 张 4x 拼图 (每张 24 格, 标准答案/我方/Zpix/Unifont 并排) 过完全部 480 格; 31 张高危格再出 8x/16x 单独放大图逐格看
9. 补充量具 (承接 lane4/lane5 的教训「腔数会漏检」): 加算连通墨块数 / 最大实心矩形 / 墨密度, 用来抓腔数抓不到的「部件并成实心带」; 本批「实心带」特征只命中 2 格 (U+8A8A 誊 21px vs 11/15; U+5341 十 是竖笔本身, 三个参考都 0 腔, 属误报)
10. 同字库一致性旁证: 从全图集里提取我方字体自己画的「目」(U+76EE, 4 横 3 腔)、「田」(U+7530, 4 格)、「典」(U+5178, 3 列)、「言」(U+8A00, 口部完整)、「申」(U+7533, 4 腔)、「耳」(U+8033, 4 横) 作为尺子 —— 本批判 B 的两字都是「同字库能画对、本字却塌了」, 可排除「12px 画风所限」这条解释
11. 判定原则: 按骨架不按像素; 只在部件封闭空间被填实 / 横画消失致部件变样 / 并成实心带 时判 B; 仅内部划分变粗、未封口判 C; 与参考的腔差 <=1 的不入存疑 (沿用 lane3 的收敛口径)

### 量具自检

- 字腔实现两份: BFS 洪水填充 (impl1) 与并查集 (impl2), 定义按协议第 5 节 (4 邻域, 只数**不接触**墨迹外接矩形边界的白区连通分量)。
- 自检范围: 480 格 x 3 列 = 1440 个字形全量跑一遍, **分歧 0 处**, 故报告中引用的腔数可信。
- 槽位放大块自检: 1440 个 16x16 槽位的 2x2 放大块**全部均匀** (非均匀块 0 个), 即出图无抗锯齿, 墨/非墨判定无灰边歧义。
- 辅助脚本: `reports/_tmp_lane6/` (`extract.py` / `analysis.py` / `flags.py` / `chamfer.py` / `calib.py` / `nn_identity.py` / `validate_mapping.py` / `metrics2.py` / `montage.py` / `zoomflag.py` / `deepzoom.py` / `cavity_labels.py` / `adjudicate.py` / `probe.py`)。

### 判定口径

- **A 类 (身份错误): 0 例。** 身份不是靠肉眼看出来的, 是四层证据合起来的:
  1. *格位映射自检*: 用 `msyh.ttc@20px` 在出图脚本指定的坐标 `(cx+4, cy+3)` 重绘每格的「标准答案」字形, 与 PNG **逐像素**比对 —— **480/480 全等, 0 处差异**;
  2. *出图源码核对*: `tools/fontgen/gen_glyphcmp_sheets.py` 里 `entries = [(ord(ch), ch, cat, ch)]`, 且三列点阵都按同一个 `cp` 取字形 —— index 的 `chars`、格内标注、Zpix 列、Unifont 列、我方列由构造绑定同一码位;
  3. *机器旁证*: 无空我方位图; 无两个码位共用同一我方位图; 无我方位图与**别的**码位的参考位图逐像素相同;
  4. *跨参考最近邻分类*: 把每格的我方位图与本批 480 个 Zpix 位图逐一做双向 Chamfer 比对 —— 本码位的 Zpix 在 **480/480 格都排进前二** (220 格第一, 其余被形近字抢到第一但差距 <= 0.27 px)。
- 另有一条**被否决**的自动化屏如实记录: 最初用「膨胀 1px 的 IoU」做身份屏, 标定发现它**没有分辨力** —— 随机错配字对的 p99 = 0.941, 而正确配对的 p50 = 0.922, 两族完全重叠; 故该屏的数字全部作废, 不参与任何判定, 身份结论不建立在它上面。
- **B 类** 只在「部件封闭空间被填实」「部件的横画消失致部件变样」「笔画并成实心带」时记。本批 2 例都额外通过了**同字库一致性检查**: 我方字体单独画的「目」(U+76EE, 4 横 3 腔)、「田」(U+7530, 4 格)、「典」(U+5178, 3 列)、「言」(U+8A00, 口部完整) 都是对的 —— 可排除「12px 画风所限」这条解释。
- **C 类**: 内部划分比参考粗、未封口、骨架仍可追踪者记 C 不往 B 靠; 与参考的腔差 <= 1 的不入存疑 (沿用 lane3 的收敛口径)。
- 像素级差异一律不算劣化 (Zpix 画风较粗, 我方与 Zpix 在简单字上也有 9 例逐像素相同, 说明两套 12px 字库在简单字上本就会重合)。

### 过程与纪律

- 本 lane 未修改 tools/fontgen/ 或任何源码; 复核期间源码可能被集成者并发改动, 不影响本结论 (判定一律以 PNG 原图为准)
- 中途更正 (如实记录): 最初靠低分辨率格内标注条带认字, 把 U+8D4A 读成「貉」、U+820C 读成「臌」等, 与 index 的实际码位不符 —— 协议第 2 节已警告不要靠标签读码位; 该误读是靠「msyh@20px 重绘标注 + 逐像素比对 480/480 全等」查出来的, 之后一律以 index JSON 为准
- 中途更正 (如实记录): 首版取墨时按「暗=墨」取反, 三列取到的是**白底黑字**的补集, 字腔数随之失真; 改为「墨=白 (v>=128)」后重跑全部量具, 本报告中的数字全部出自修正后的实现
- 字腔数不可单独定案: 本批腔差(我方 vs 两个参考的较小者) >=2 的共 12 格 —— 誊(差3)/算/腆/摄/属/题/耸/酸/穗/魏/巍/审。其中 10 格是「未封口 / 内部划分变粗」而骨架仍可追踪, 只记 C; 唯一判 B 的「誊」另有「墨更多(66>59)却腔更少(1<4)」的填实签名。另有「省」腔差仅 1 (2/3/3) 却是「目→日」的部件塌陷, 靠同字库一致性检查才抓得到 —— 即 docs/glyph-identity-verification.md 第 5.1 节记载的「腔数会漏检」。「顽」(0/2/0) 因两个参考自相矛盾, 归 C 不判
- 存量上下文: 协议文档 docs/glyph-review-protocol.md 与 docs/glyph-identity-verification.md 第 5.1 节已载明 lane6 = sheets 29-33 / 480 字, 与本 lane 分配一致
