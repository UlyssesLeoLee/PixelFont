## 5. 方法说明

1. 协议核对: 读 docs/glyph-review-protocol.md, 判定口径按 A/B/C 三类, 参考列确认为 Zpix + Unifont (index refs=['zpix','unifont-16']), 槽位 16x16 (index slot_w/slot_h=16), 无溢出污染
2. 格位映射自检: 把 index JSON 的 576 个码位逐格与 PNG 内的蓝色标注做模板匹配 (msyh 12px, 最佳 IoU>=0.6), 576/576 一致; 唯一 0.59 的格子 (U+9F9F) 目视确认标注即 U+9F9F
3. 量具自检: 字腔数用两份独立实现 (BFS 洪水填充 + 扫描线并查集), 对 576 格 x 3 列共 1728 个字形跑一遍, 分歧 0 处, 数字可用
4. 目视复核: 每格裁切后按 8x 放大, 48 张对照拼图 (每张 12 格, ours|zpix|unifont) 逐张过完 576 格; 存疑格再用 16x/24x 单独放大
5. 判定原则: 按骨架不按像素; 只在部件封闭空间被填实 / 横画消失致部件变样 / 并成实心带 时判 B; 仅内部划分变粗判 C
6. 旁证检查: 无空字格; 无不同码位共用同一我方位图; 16 个我方位图与同码位 Zpix 逐像素相同 (皆为简单字, 属正常)

### 量具自检

- 字腔实现两份: BFS 洪水填充 (impl1) 与扫描线并查集 (impl2), 定义按协议第 5 节 (4 邻域, 只数**不接触**墨迹外接矩形边界的白区连通分量)。
- 自检范围: 576 格 x 3 列 = 1728 个字形全量跑一遍, **分歧 0 处**, 故报告中引用的腔数可信。
- 辅助脚本: `reports/_tmp_lane3/` (`extract.py` / `cavities.py` / `montage.py` / `zoom.py` / `cmp.py` / `ascii.py` / `validate_mapping.py`)。

### 判定口径

- A 类 (身份错误): 0 例。576 格逐格与两个参考对读, 未发现我方画成了别的字; 另外机器侧交叉验证: 无空字格, 无两个不同码位共用同一我方位图, 无我方位图等于**别的**码位参考字形。
- B 类: 仅当部件的封闭空间被填实 (嘎)、部件内部笔画并成实心带 (酱)、部件因横画消失而变样 (藉的日→口)、部件封闭空间整个消失 (蛤的虫口未闭合) 时才记 B。
- C 类: 结构仍完整可追踪、只是内部划分比参考粗者, 记 C 而不往 B 靠。
- 像素级差异一律不算劣化 (Zpix 画风较粗, 但我方与 Zpix 在简单字上也有 16 例逐像素相同, 说明两套 12px 字库在简单字上本就会重合)。

### 过程与纪律

- 全部判定以出图 PNG 原图为唯一底本; 复核拼图为便于阅读做了黑白反相, 像素数据未改动。
- 未修改 `tools/fontgen/` 或任何源码; 复核期间源码可能被集成者并发修改, 不影响本结论。
- 本 lane 没有出现"早先结论与最终产物不一致"的情况 (首次成稿即为上述数值)。
